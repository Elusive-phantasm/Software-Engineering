## 5 严重级别准则（避免用「感觉」定级）

| 级别 | 判据（满足其一即可） | 最低证据要求 |
|---|---|---|
| **P0 阻断** | 核心链路（成交→撤销→回售）在**默认配置**下必然失败并留下不可自愈状态；或权限提升/越权改密等安全缺陷 | **必须**有运行期实测（状态码 + DB 终态 + 服务端异常）；纯静态只能定为「P0 候选」 |
| **P1** | 需求明确要求但完全缺失的能力；或用户被明确误导且状态与提示不一致；或安全/数据缺陷有前提条件 | 实测，或「静态 + 代码路径可判定」二者之一，须写明缺哪一半 |
| **P2** | 测试资产、文档、构建产物、可维护性；不影响运行期正确性 | 静态检索即可，须给可复制命令 |
| **P3** | 表述/命名/注释；不改行为 | 同上 |

附加规则：

1. **同一修复点收敛多条**（如 BUG-002/003 同一行代码）时，级别取高者，另一条注明「同源，随主条关闭」。
2. **P0 必须写「恢复路径」**：卡死数据如何解、是否需人工 SQL、谁执行。
3. **需求冲突项**（实现与 SRS 不一致）**不得自行定级为「缺陷已成立」**，须写「待产品裁定」，并给两个方向的关闭条件。

### 6.2 关闭条件（可观测断言，逐条）

**BUG-001**

- 断言：同一条「申请中」订单，对方再调 `POST /api/orders/{id}/cancel` → `200`；DB `status='已撤销'`、`cancel_judgement='已免责'`、`judgement_at IS NOT NULL`、`cancel_requester_id IS NULL`、`cancel_approver_id`/`cancel_approved_at` 非空；商品 `status='在售'`、`off_shelf_reason IS NULL`；该订单**无**「撤销违约」信用记录、撤销方信用分不变。
- 反向验证：同一脚本在**未修复版**必须红，并记录真实状态码。
- **必须先解决的矛盾**：清单写「实际 500/5000」，但代码路径上 `DataIntegrityViolationException` 应命中 `GlobalExceptionHandler.handleIntegrity` → `422/2001`。登记须补：服务端异常类、是否命中 `handleIntegrity`、事务提交点是否在控制器返回之后（`TransactionSystemException`）。**这条不解释清楚，等于没有可复现证据。**
- 恢复：登记「已卡死行」的处置办法（人工清空 `cancel_requester_id` 等三列，或删库重建），并写明由谁执行。
- **待验证假设（须在实测中判定，不作结论）**：MySQL 对 CHECK 违反返回 vendor code `3819` / SQLState `HY000`；若该错误未被 MyBatis/Spring 归入 `DataIntegrityViolationException`，就会落到 `GlobalExceptionHandler.handleOther` → `500/5000`。这与清单自述的「500」一致，但**必须**用服务端异常类名 + 是否命中 `handleIntegrity` 来证实或推翻；两种结果对应不同的「关闭条件写法」（500 需同时修异常映射，422 只需修写入值）。
- 回归：ST-11（卖家已封禁分支）、撤销后二次成交、审计 `order.cancel.request`/`order.cancel`、通知两条。

**BUG-002 / BUG-003**

- 断言组：匿名 → `401/1001`；学生令牌 → `403/1003`「仅管理员可执行该操作」；管理员 + 错原密码 → `422/2001`「原密码不正确」；新=旧 → `422/2001`；合法改密 → `200`，DB `must_change_password=0`，旧口令登录 `401`、新口令 `200`。

| 是否真是 PNG | magic + IHDR + 尾块 | `89504E470D0A1A0A`；IHDR **1×1**；尾块 `IEND` → **合法 1×1 PNG** |
| HEAD 版本是否相同 | `git show HEAD:tools/smoke.mjs` | 同为合法 data URL（133 字符行） |

**判定**：`BUG-006` 的「现象」来自**取证工具的展示省略**，不是文件内容；「`git show HEAD` 同样为占位符」这句也随之失效。该条应撤回，并把「取证方法」本身登记为 P3 流程缺陷——**证据必须来自文件字节或运行输出，不来自被截断的展示文本**。

> 顺带：`PNG` 可用意味着「图片上传链路不可测」这个结论也不成立；但**是否存在别的上传失败原因**仍未验证（本轮未跑），不得反过来写成「通过」。
