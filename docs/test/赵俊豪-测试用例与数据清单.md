## 1 使用说明

### 1.1 四个结论词（写错整份记录作废）

| 词 | 使用条件 |
|---|---|
| **通过** | 按步骤执行过，实际结果与预期逐项一致，证据在案 |
| **不通过** | 执行过，实际与预期不符（**必须开 BUG**） |
| **阻塞** | 前置条件不满足（环境／数据／等别人），没走到判定点 |
| **未验证** | 完全没执行（**不许写成「无问题」**） |

### 1.2 编号与层级

- 编号：`ZJH-<需求>-<序号>`（如 `ZJH-SC04-01`）。与仓库外 `TC-xxx`／`BB-xxx` 不冲突；TC／BB 的映射在各表「关联」列注明。
- 层级：`I`=接口（HTTP 契约与状态码）· `D`=数据库集成（约束／行数／多连接）· `U`=页面级 · `E`=端到端 · `P`=性能 · `M`=人工计时。
- 优先级：`P0`=主链与状态／权限／编号（必跑）· `P1`=边界与通知 · `P2`=性能与专项。

### 1.3 判据代号（避免每行重复长句）

| 代号 | 含义 |
|---|---|
| **J1** | 状态与字段：`status`／`offShelfReason`／`reviewNote`／`publishedAt`／`id` 与预期逐项一致 |
| **J2** | 错误契约：HTTP 状态 + 业务码（2001／1003／3001／1004／404）+ 提示语含关键片段 |
| **J3** | 不变性：商品数、订单数、信用分、通知数、审计数、收藏数不因被拒而变 |
| **J4** | 可见性：列表／搜索结果出现或不出现 |
| **J5** | 编号与时间：`id` 不变；`publishedAt` 刷新或不刷新 |
| **J6** | 通知：接收人、类型、条数、已读状态 |
| **J7** | 阈值：每次样本／每人时长 |
| **J8** | 数据库：约束与行数核对（SQL 结果） |

## 3 读码结论：接口契约（用于写步骤与断言）

> 以下为**静态阅读**结果（`ProductController`／`AdminProductController`／`ProductService`／`FavoriteService`／`NotificationService`／`PermissionService`／`schema.sql`），执行时须以实际响应为准；若实际与本节不符，先按「实现漂移」记录，再判断是否 BUG。

| 能力 | 方法与路径 | 关键实现事实（影响用例） |
|---|---|---|
| 分类 | `GET /api/categories` | 单层 8 类；`onSaleCount` 只统计 `在售` 且未删除 |
| 列表／搜索 | `GET /api/products` | **恒加 `status=在售` + `deleted_at IS NULL`**；`pageSize` 上限 **60**、默认 12；`keyword` 匹配标题或描述（LIKE）；`categoryId`／`condition`（仅四值）／`minPrice`／`maxPrice`；`sort` = latest（默认，按 `publishedAt` 降序）／priceAsc／priceDesc／hot |
| 详情 | `GET /api/products/{id}` | 公开；非本人非管理员仅 `在售`／`已售出` 可见，`待审核`／`已下架` 返回 **404**；非本人访问 `viewCount +1` |
| 发布 | `POST /api/products` | 守卫：已认证 + 未封禁 + 信用分≥60；**先查在售 5 件上限，再校验图片**；价格字符串；图片 data URL；成功即 `待审核`，提示「已提交审核，等待管理员审核」 |
| 编辑 | `PATCH /api/products/{id}` | 守卫：已认证 + 未封禁（**不查信用分**）；本人；仅 `待审核`／`在售` 可编辑；写入 `待审核`、清空 `offShelfReason`／`reviewNote`／审核人、`publishedAt=now`；**`images=[]` 不删除旧图**（跳过图片分支）；图片 >9 在写库后抛错（事务回滚） |
| 撤回 | `POST /api/products/{id}/withdraw` | 本人；`待审核` 限定；→ `已下架（卖家撤回）`；**不发通知**；`已售出` 先拒绝 |
| 下架 | `POST /api/products/{id}/take-down` | 本人；`在售` 限定；→ `已下架（卖家主动下架）`；通知收藏者；`待审核` 提示「只能撤回」；`管理员违规下架` 商品返回 **1003** |
| 删除 | `DELETE /api/products/{id}` | 本人；仅 `已下架`；**`管理员违规下架` 返回 1003**；软删除 `deleted_at`；`在售` 提示先下架；`待审核` 提示只能撤回；`已售出` 拒绝 |
| 重提 | `POST /api/products/{id}/resubmit` | 本人；仅 `已下架`；允许原因 = `审核不通过`／`卖家撤回`；`管理员违规下架`／`撤销后不可交易`／`卖家主动下架` 均拒绝；复查在售 5 件；可选 body 改内容；→ `待审核`，清空审核字段，`publishedAt=now`；**不校验图片 >9** |
| 我的商品 | `GET /api/me/products` | 返回 `total`（本人未删除商品数）+ `groups` 固定四键；按 `publishedAt` 降序 |
| 管理端列表 | `GET /api/admin/products` | 无参 → 待审队列（`publishedAt` 升序）；带 `status` → 该状态，`LIMIT 300`；`keyword` 只匹配标题 |
| 审核通过 | `POST /api/admin/products/{id}/approve` | 仅管理员；仅 `待审核`；→ `在售`，清下架原因，写 `reviewNote="审核通过"`；通知卖家 + 收藏者 |
| 审核驳回 | `POST /api/admin/products/{id}/reject` | 仅管理员；仅 `待审核`；`categoryCode` 必须是 §4.3 的 18 类之一（大小写不敏感），`reason` 非空；→ `已下架（审核不通过）`；`reviewNote = 编号 + 名称 + ： + 原因`（截断 200）；通知卖家 |
| 强制下架 | `POST /api/admin/products/{id}/force-off` | 仅 `在售`／`待审核`；需类目编号 + 理由；→ `已下架（管理员违规下架）`；默认扣 −10（`deduct=false` 可关）；通知卖家 |
| 撤销处置 | `POST /api/admin/products/{id}/restore` | 仅 `已下架（管理员违规下架）`；理由必填；→ `在售`；扣分**不回滚**；通知卖家 + 收藏者 |
| 禁售清单 | `GET /api/admin/products/forbidden-categories` | 返回 18 个编码→名称，顺序 A1…E2 |
| 收藏 | `POST /api/favorites`、`DELETE /api/favorites/{productId}`、`GET /api/me/favorites` | 已登录即可（**不要求认证**）；组合唯一；上限 100；**不校验商品状态**（仅查未删除）；收藏页对非在售返回 `invalid=true` + `invalidLabel="已失效"` |
| 通知 | `GET /api/notifications`、`POST /api/notifications/{id}/read`、`POST /api/notifications/read-all`、`GET /api/badge` | 按 `createdAt` 降序；只返回最近 **90 天**；置读仅本人（他人 1003）；`badge` 分列通知与私信未读数 |
| 错误码 | `ErrorCode.java` | 1001 未登录(401)／1003 无权(403)／1004 封禁(403)／2001 参数(422)／3001 状态(409)／3002 不存在(404)／3003 冲突(409)／5000 内部(500) |

## 4 读码结论：实现事实与风险（先登记，执行时逐条验证）

> 这些不是「已确认 BUG」，是**读码得到的可验证假设**。执行时按对应用例判：与 SRS 不符即开 BUG；SRS 本身留白则记「需求缺口／未验证」，不自己定口径。

| 编号 | 事实／风险 | 依据 | 处理方式（对应用例） |

### 5.6 造数（测试夹具，仅本地环境；执行前记录 SQL 文件与输出）

**NFR-01：50 卖家 × 4 件 = 200 件在售**

```sql
-- 0) 取种子账号的密码哈希（避免 INSERT … SELECT 引用目标表）
SET @pwd := (SELECT password_hash FROM students WHERE email = 'lin@campus.edu');

-- 1) 50 个已认证卖家（仅供压测；每卖家 4 件，满足 BR-02 的「每人在售≤5」）
INSERT INTO students (email, student_no, nickname, real_name, password_hash, cert_status,
                      account_status, credit_score, review_count, verified_dispute_count,
                      resubmit_count, failed_login_count, registered_at, created_at, updated_at)
WITH RECURSIVE n(n) AS (SELECT 1 UNION ALL SELECT n + 1 FROM n WHERE n < 50)
SELECT CONCAT('nfr01-', LPAD(n, 2, '0'), '@campus.edu'),
       CONCAT('9000', LPAD(n, 4, '0')),
       CONCAT('NFR01-', LPAD(n, 2, '0')),
       CONCAT('压测卖家', LPAD(n, 2, '0')),
       @pwd, '已认证', '正常', 100, 0, 0, 0, 0, NOW(), NOW(), NOW()
FROM n;

-- 2) 50 × 4 = 200 件在售；价格 100～4,999,999 分；分类轮转；发布时间打散
INSERT INTO products (title, description, price_cents, item_condition, seller_id,
                      category_id, status, published_at, view_count, created_at, updated_at)
WITH RECURSIVE s(n) AS (SELECT 1 UNION ALL SELECT n + 1 FROM s WHERE n < 50),
               k(i) AS (SELECT 1 UNION ALL SELECT i + 1 FROM k WHERE i < 4),
               c AS (SELECT id, ROW_NUMBER() OVER (ORDER BY id) rn FROM categories)
SELECT CONCAT('压测商品-', LPAD(s.n, 2, '0'), '-', k.i),
       CONCAT('NFR-01 压测数据：卖家 ', s.n, ' 的第 ', k.i, ' 件，描述完整，不含联系方式。'),
       100 + (s.n * 1000 + k.i * 137) % 4999900,
       ELT(1 + (s.n + k.i) % 4, '全新', '九成新', '七成新', '其他'),
       st.id, c.id,
       '在售', DATE_SUB(NOW(), INTERVAL (s.n * 4 + k.i) MINUTE), 0, NOW(), NOW()
FROM s
CROSS JOIN k
JOIN students st ON st.email = CONCAT('nfr01-', LPAD(s.n, 2, '0'), '@campus.edu')
JOIN c ON c.rn = ((s.n + k.i) % 8) + 1;

-- 3) 每件 1 张图（默认复用种子图；若要测「图片完整呈现」，
--    改为 200 张互不相同的 ≤500KB JPEG，并把 20 件设成 9 张用于详情页多图）
INSERT INTO product_images (product_id, seq, path)
SELECT p.id, 1, '/uploads/product/seed-1.svg'
FROM products p WHERE p.title LIKE '压测商品-%';

-- 4) 自检：必须 200 条在售、50 个卖家、每人恰好 4 件
SELECT COUNT(*) FROM products WHERE status = '在售';
SELECT COUNT(DISTINCT seller_id) FROM products WHERE status = '在售';
SELECT MAX(c) FROM (SELECT COUNT(*) c FROM products WHERE status = '在售' GROUP BY seller_id) t;
```

> **口径必须写清**：SRS 写明「200 条是整个数据集还是单次展示量」待确认。本方案按「**全站数据集 200 条在售**」造数，并用 `pageSize=12` 分页访问；接口单页上限 60，**无法一次展示 200 条**。若组长按「单次展示 200 条」口径验收，本项记「口径不可满足／待确认」，不得自行改判达标。
> **图片**：若要统计「内容呈现完毕」含图片，须用 200 张互不相同的 JPEG（每张 ≤500KB，建议 150KB），并**冷启动清缓存**；复用种子 SVG 会因浏览器缓存严重低估耗时。

**NFR-06：10 名受试者账号**（SQL 同 NFR-01，邮箱 `nfr06-01…10`，昵称 `NFR06-01…10`）；素材包固定一份：标题「宿舍置物架 三层」、描述「九成新，宿舍自用一学期，无破损，可拆装；图书馆门口自取。」、价格 `25.00`、成色「九成新」、分类「生活用品」、图片 1 张（手机拍摄 2MB 原图）。
