### 2.4 每个功能怎么写（照这个格式抄）

**示例：UC-06 下单**

| 字段 | 内容 |
|---|---|
| 参与者 | 学生（买家） |
| 目标 | 买家锁定想要的商品并生成订单 |
| 前置条件 | 已登录、已实名、商品处于「在售」、不是自己发布的 |
| 触发条件 | 买家点击「立即购买」 |
| 主事件流 | 1. 点击「立即购买」<br>2. 系统检查商品状态和买家资格<br>3. 选交付方式<br>4. 提交订单<br>5. 系统锁定商品并生成订单 |
| 辅事件流 | A. 商品已被别人预订 → 提示「该商品已被预订」，返回列表<br>B. 买家未实名 → 提示「请先完成实名认证」<br>C. 买家是自己 → 提示「不能购买自己发布的商品」 |
| 后置条件 | 商品变「已预订」；生成一条待支付订单 |
| 发生频率 | 上课日 9:00–23:00 约 200 次/天，开学季翻倍 |

19 个功能都照这个表填。**辅事件流**那栏最重要——就是「如果出错了会怎样」，尽量多写几条。

### 2.5 两条要注意的

⚠️ **不要写系统内部怎么实现**。比如「用加密算法存订单」「用 Redis 缓存」——那是设计，不是需求。
写进去会被判「粒度太细」。你只写**用户看得见的行为**。

⚠️ **一件功能只说一件事**。如果你发现某条里塞了两个动作（「A 和 B」这种），就拆成两条。
