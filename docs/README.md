# 文档索引

> 约定：每类文档只保留**当前有效版本**，版本号写在文件头；旧版不再在目录里留存副本，
> 需要时用 `git log` / `git show` 回溯。

| 目录 | 收什么 | 当前有效文件 |
|---|---|---|
| [`requirements/`](requirements) | 需求类 | `SRS.md`（V2.1）、`需求覆盖矩阵.md` |
| [`architecture/`](architecture) | 架构文档组 | `软件架构设计说明书.md`（ADD 主文档）、`架构确认与决策记录.md`（Q + ADR）、`架构分工与接口所有权表.md` |
| [`design/`](design) | 设计类 | `接口与关键设计说明书.md`（接口契约全集）、`数据库设计.md`（表结构、索引、约束） |
| [`test/`](test) | 测试与验收 | `验收与测试记录.md`、`压测结果.json`、`screenshots/`、`走查记录/`（场景与原型走查记录及截图证据） |
| [`tasks/`](tasks) | 任务、分工与阶段计划 | `分阶段实现与测试计划.md`、`分工通知/`、`分工成果/`（四名成员的需求阶段成果） |
| [`reports/`](reports) | 阶段报告 | A 报告（需求分析质量验证）、B 报告（AI 智能体使用验证）、成员 AI 使用报告 |
| [`course/`](course) | 课程材料 | 老师下发的模板与操作指引，非项目产出 |
| [`deployment/`](deployment) | 部署与运维 | 待补，见该目录 README |

**从哪开始**：先看 [`基线索引.md`](基线索引.md)——它登记了每一类文档的当前版本、尚未关闭的 Q，以及现在能不能开工。

## requirements

- `SRS.md`：《软件需求规格说明书》V2.1（2026-11-05），24 个用例、22 条业务规则，版本号见文件头。
- `需求覆盖矩阵.md`：UC / BR / ST / AT / NFR → 代码位置的逐条映射。

## architecture

- `软件架构设计说明书.md`：ADD 主文档，按课程四层次组织，含 10 张 Mermaid 图与静态度量。
- `架构确认与决策记录.md`：待确认问题 Q-01～Q-06 与架构决策 ADR-001～006 全文。
- `架构分工与接口所有权表.md`：75 个接口逐个归属到人。
- （讨论稿、基线版等过程版本已按约定移除，`git log` 可回溯。）

## design

- `接口与关键设计说明书.md`：REST 接口契约，含权限、入参、返回、错误码。
- `数据库设计.md`：ER 关系、表结构、索引与 CHECK 约束。

## test

- `验收与测试记录.md`：冒烟 72 项、浏览器 e2e 20 项、压测抽样结果与执行方式。
- `压测结果.json`、`screenshots/`：NFR-01/02 压测抽样数据与界面截图（2026-11 从 `campus-trade/docs/` 并入）。
- `走查记录/`：四名成员的 A.5 场景走查、A.6 原型走查记录，以及对应截图证据。

## tasks

- `分阶段实现与测试计划.md`：S1～S3 阶段目标、准入检查与验收单模板。
- `分工通知/`：各阶段下发的成员任务说明（含需求文档阶段、走查分工、软件测试阶段）。
- `分工成果/`：成员在需求阶段的成果，只保留最后一次修改版。
  - `功能/`：赵俊豪，用例建模与用例图
  - `规则与状态/`：吕锦浩，业务规则、状态机 SM-01～SM-04、PV-03 状态走查
  - `数据与权限/`：马歆远，UML 类图、数据字典、权限矩阵、非功能需求、一致性检查
  - `目标树、术语表、架构上下文/`：目标树、系统上下文图、术语表、边界问题决议

## reports

- `A报告/`：《需求分析质量验证报告》，对应课程 A 部分。
- `B报告/`：《AI 智能体使用验证报告》，对应课程 B 部分。
- `AI使用报告/`：成员各自提交的 AI 使用报告（docx / md / pdf 与证据截图）。

## course

- `学生需求分析与AI智能体使用验证报告.md`：课程模板（A/B 两部分要求）。
- `架构设计后确认与分阶段实现操作指引_学生版.md`：架构阶段的流程与文档要求。
