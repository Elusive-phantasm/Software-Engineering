# 权限矩阵

## 角色及判定口径

游客为未登录访问者；未认证学生、已认证学生为已登录且处于对应认证状态的学生；管理员是独立管理角色。四类角色及基础权限矩阵按已定案规则维护，不把管理员自动视为已认证学生。一个自然人若同时拥有学生和管理员身份，如何切换角色待确认；当前按本次操作的有效角色判定，禁止借管理员身份发布、下单或评价。

“允许”仅表示通过角色权限条件，仍需通过对象归属、数据可见范围及正式业务状态条件；“拒绝”表示基础角色无权。未认证学生浏览权限不因认证状态而被收回；锁定登录规则不擅自改变浏览或认证状态。

|---|---|---|---|---|---|
| 浏览商品 | 允许 | 允许 | 允许 | 允许 | 若目标无访问范围，提示“该商品暂不可查看”，不泄露内部审核详情；执行下述统一不变与审计规则 |

| 下单 | 拒绝 | 拒绝 | 允许 | 拒绝 | 游客：“请先登录并完成学生认证”；未认证：“请先完成认证”；管理员：“管理员无下单权限”；执行下述统一不变与审计规则 |

| 审核商品 | 拒绝 | 拒绝 | 拒绝 | 允许 | 游客：“请先登录管理员账号”；两类学生：“仅管理员可审核商品”；执行下述统一不变与审计规则 |

| 查看他人信用变动明细 | 拒绝 | 拒绝 | 拒绝 | 允许 | 非管理员：“无权查看他人信用变动明细”；执行下述统一不变与审计规则 |
| 驳回举报 | 拒绝 | 拒绝 | 拒绝 | 允许 | 仅管理员可驳回举报；执行下述统一不变与审计规则 |
| 扣信用分 | 拒绝 | 拒绝 | 拒绝 | 允许 | 仅管理员可执行扣信用分；具体触发条件与幅度按正式信用规则执行 |
| 撤销错误处置 | 拒绝 | 拒绝 | 拒绝 | 允许 | 管理员可撤销错误处置并恢复其造成的业务影响；须保留原处置并追加撤销记录；具体冲突处理待确认 |
| 取消订单 | 拒绝 | 拒绝 | 允许 | 拒绝 | 仅已认证学生可按正式业务条件取消订单；执行下述统一不变与审计规则 |
| 查看消息通知 | 拒绝 | 允许 | 允许 | 允许 | 仅查看当前账号可访问的通知；不得读取他人通知 |
| 下架自己的商品 | 拒绝 | 拒绝 | 允许（仅限本人发布的商品） | 拒绝 | 仅允许发布人操作本人商品；管理员下架违规商品仍使用独立权限行 |

浏览商品一行四类角色均允许，不额外设置登录或认证门槛。目标不存在、已不在公开范围等情形应按对象可见性处理，不能伪装成角色无权；具体可浏览商品状态须与原型和状态图对齐。

## 允许操作的对象与业务条件

| 操作 | 允许范围与仍待明确的条件 |
|---|---|
| 浏览商品 | 公开可浏览的商品；可浏览状态范围待确认；不能因此读取学生隐私 |
| 发布商品 | 本人发布；字段和业务条件合法后才成功；是否初始进入待审核待确认 |
| 下单 | 本人下单；可下单商品状态、自购限制、并发成交规则待确认 |
| 评价 | 本人提交；交易资格、可评状态与次数待确认，不能把角色允许等同于可评所有人 |
| 举报 | 仅已认证学生可提交；举报对象仅限商品，不支持举报学生或评价 |
| 审核商品 | 管理员在可审核状态下执行；审核结论与后续状态须由正式规则确定 |
| 下架违规商品 | 管理员仅可对在售或已预订商品强制下架；待审核商品须通过商品审核拒绝处理；其他状态不得直接强制下架。对已预订商品的关联订单影响待确认 |
| 删除他人评价 | 仅管理员；删除依据、历史保留及信用影响待确认 |
| 查看他人信用分（仅分数） | 校内任意学生可查看其他学生分数；不包含信用变动明细；管理员也可查看 |
| 查看他人信用变动明细 | 仅管理员可查看他人明细；本人明细通过“查看本人信用记录”权限查看 |
| 驳回举报 | 管理员对符合处理条件的举报执行；处理结果及状态更新按正式规则确定 |
| 扣信用分 | 管理员按正式信用规则执行；具体触发条件、幅度与记录方式按正式规则确定 |
| 取消订单 | 已认证学生仅在正式业务条件允许时取消本人可取消的订单；状态条件待正式状态图确认 |
| 查看消息通知 | 当前登录主体仅可查看发给自己的通知；具体通知触发类型按功能说明确认 |
| 下架自己的商品 | 仅已认证学生可下架本人发布的商品；与管理员“下架违规商品”分开处理 |

## 本人数据与他人数据（正式需求及必要补充）

| 操作 | 游客 | 未认证学生 | 已认证学生 | 管理员 | 权限拒绝后的处理 |
|---|---|---|---|---|---|
| 查看手机号、宿舍地址 | 拒绝 | 仅本人 | 仅本人 | 原文允许；建议限定必要管理场景并审计 | 提示“仅本人或具备相应管理权限的管理员可查看”；不返回真实值；不改变业务数据与状态 |
| 查看本人信用分（正式需求） | 拒绝 | 允许 | 允许 | 不适用 | 游客提示“请先登录”；只读取本人分数，不改变分数 |
| 查看我的订单 | 拒绝 | 允许 | 允许 | 拒绝 | 仅返回当前学生本人的订单；不得通过换编号读取他人数据 |
| 查看本人信用记录 | 拒绝 | 允许 | 允许 | 允许 | 仅本人可查本人明细；管理员可在管理职责范围内查看；不得修改记录 |

“本人”通过当前登录主体与学生学号的归属判定，不能采信用户自行填写的学号来扩大范围。查看本人不自动赋予修改本人信用分、信用记录、认证状态或删除评价的权限。上述权限为已定案需求；具体页面入口和业务状态限制仍须与对应功能说明及正式状态图对齐。

## 权限控制业务规则

1. **角色与对象校验**：每次实际操作都检查有效身份、角色、对象归属和字段可见范围。隐藏按钮只能辅助交互；直接指定他人编号、换入口或重复提交也必须受同样限制。默认不返回拒绝访问对象的手机号、地址、信用分或举报人身份。
2. **权限拒绝不改变业务**：被拒绝时不创建商品、订单、评价、举报或信用记录，不变更商品、订单、举报处理状态，不删除评价，不更新信用分；不得因一次被拒绝操作扣信用分。允许追加必要的安全审计记录，审计记录不算业务实体变动。
3. **权限拒绝与状态拒绝区分**：角色无权时使用矩阵中的身份或权限提示；角色有权但状态不满足时提示“当前业务状态不支持该操作”，并说明可安全公开的原因。两类拒绝均保持本次操作前的业务数据与状态不变，审计原因分别记录。管理员强制下架仅适用于在售或已预订商品；待审核商品须通过商品审核拒绝，属于审核状态流程，不得作为强制下架处理。其他状态条件按正式规则执行。
4. **拒绝提示要准确**：未认证学生发布时提示认证，不能误报系统故障；未认证学生下单时提示“请先完成认证”，该拒绝源于认证状态不满足；管理员下单时提示角色无权，不能诱导管理员完成学生认证来绕过限制；普通学生查看他人信用分时允许返回分数，但不得展示信用变动明细；查看他人信用变动明细时应提示无权。
5. **必要审计**：记录权限拒绝、敏感个人信息读取和管理员审核／下架／删除／驳回举报／扣信用分／撤销处置等管理操作。审计至少含操作时间、操作者可得标识（游客使用会话标识）、有效角色、动作、目标可得标识、结果和原因类别；不得写入支付密码、登录密码、完整手机号或完整宿舍地址。撤销错误处置时恢复其造成的业务影响，保留原处置记录并追加撤销记录；具体撤销状态范围、与后续操作冲突时的恢复规则、审计关联字段及保留期限待正式规则确认；不新增独立审计管理功能或审计实体设计。
6. **登录失败是独立安全行为**：原文连续失败 5 次锁定 15 分钟会改变登录失败计数和锁定截止时间，并可追加安全日志；这些不属于“发布／下单被拒绝”导致的业务状态变化。不得顺带变更认证状态、商品状态、订单状态或信用分。
7. **在业务状态并发变化时**：候选要求为以提交执行时检查到的合法条件为准；若其他操作已使商品不可下单，应拒绝本次操作，不留下本次新订单或错误预订状态。如何识别唯一有效订单须由业务规则负责人确认；本次无权要求覆盖其他合法操作的结果。
8. **允许操作的影响不混同于拒绝**：管理员审核、下架和删除成功后的状态、历史保留及关联影响须与正式规则对齐；本草案不擅自指定自动取消订单或扣分。错误的管理员处置应可撤销并恢复该处置造成的业务影响，且保留原处置、追加撤销操作记录；涉及多次处置或后续状态变化时的恢复顺序待正式规则确认。举报提交成功本身不等于违规已经成立；是否触发自动下架或其他处置缺少正式定义，待组长确认，本草案不预设自动处置规则。

## 典型走查输入与期望（不另分配 SC 或 V 编号）

| 输入场景 | 提示与判断 | 业务数据／状态的期望 | 可检查的审计 |
|---|---|---|---|
| 游客尝试发布商品 | 请先登录并完成学生认证；权限拒绝 | 不新增商品，不产生待审核商品 | 权限拒绝；角色为游客 |
| 未认证学生尝试下单 | 请先完成认证；认证状态不满足 | 不新增订单；商品不变成已预订 | 记录状态拒绝；不记录敏感明文 |
| 已认证学生指定他人学号读取手机号 | 仅本人或具备相应管理权限的管理员可查看 | 不返回手机号；本人、目标学生及业务对象均不变 | 拒绝及目标标识；不含真实手机号 |
| 管理员尝试下单或评价 | 管理员无下单权限／管理员无评价权限 | 无新增订单／评价；不改变商品或信用分 | 权限拒绝；角色为管理员 |
| 已认证学生删除他人评价 | 仅管理员可删除他人评价 | 原评价保留；信用分不变 | 权限拒绝 |
| 已认证学生查看交易对方信用分 | 允许，仅显示分数 | 返回分数，不返回信用变动明细 | 访问结果可追溯；不改变分数与信用记录 |
| 管理员提交举报 | 管理员不能以举报人身份提交举报 | 不新增举报记录 | 权限拒绝 |
| 已认证学生下单时商品不满足正式可下单状态条件 | 当前业务状态不支持该操作；状态拒绝 | 不产生本次订单；无本次错误状态变更 | 业务状态拒绝，不误记角色无权 |
| 管理员审核状态不允许审核的商品 | 当前业务状态不支持该操作；状态拒绝 | 商品原状态及订单不变 | 业务状态拒绝 |
| 管理员巡查发现违规商品 | 管理员直接进入审核或处置流程；待审核商品走审核拒绝，在售／已预订商品方可强制下架 | 不创建举报记录；仅对允许状态执行对应操作 | 管理操作可追溯 |

| 已认证学生查看本人信用记录 | 允许，仅返回本人记录 | 不得读取他人信用记录 | 访问范围按权限判定 |
| 未认证学生查看消息通知 | 允许，仅返回当前账号通知 | 不得读取他人通知 | 访问结果可追溯 |
| 已认证学生下架他人商品 | 仅限本人发布的商品 | 他人商品保持原状态 | 权限拒绝 |
| 管理员驳回举报、扣信用分或撤销错误处置 | 驳回举报、扣信用分和强制下架为并列处置；错误处置可撤销 | 按规则分别更新处理结果／信用分／处置影响；撤销时恢复并另记操作 | 保留操作记录 |

上述为可用于原型和后续系统验收的预期结果，未执行真实系统测试。状态相关场景的具体初态由正式状态转换表补齐。
