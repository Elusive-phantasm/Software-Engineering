## ☐ 1. 走 SC-02 权限流程

按管理员视角走，重点核这几处：

| 走到哪 | 你要核的 |
|---|---|
| 审核商品 | 只有管理员能审；管理员能不能发布/下单（不能） |
| 处理举报 | **管理员能不能自己举报**？→ 不能，管理员直接处置 |
| 强制下架 | 下架的是「在售/已预订」商品，不是「待审核」（待审核走审核拒绝） |
| 扣信用分 | 扣分是处置手段，和 `驳回举报` `强制下架` 并列 |
| 撤销处置 | 处置错了能不能恢复？→ 应能（BR-23 + ST-28），且要留痕 |

## ☐ 2. 权限六问，逐条当场核

| # | 问题 | 正确答案 |
|---|---|---|
| 1 | 游客能发布商品吗 | ❌ 拒绝 |
| 2 | 未认证学生能下单吗 | ❌ 拒绝，提示"请先完成认证" |
| 3 | 已认证学生能看**他人信用分**吗 | ✅ 能看**分数**，不能看变动明细 |
| 4 | 管理员能举报吗 | ❌ 不能（直接处置，不走举报入口） |
| 5 | 卖家能下架**别人的**商品吗 | ❌ 只能下架自己发布的 |
| 6 | 管理员能下单/发布/评价吗 | ❌ 全拒绝 |

**任何一条对不上，当场记问题。** 记的时候注明是哪一种拒绝：

- **角色无权**（这个人根本不该做这件事）
- **状态不允许**（这个角色能做，但当前状态不许做）

两类拒绝的提示语不一样，混在一起等于需求没定义清楚。

**填写规则**：

1. 验证编号 = `PV 编号 - 步骤号`，不要只写 PV-02
2. 「预期结果」不要改，那就是判据
3. 「实际结果」只能写 **通过 / 失败 / 未验证** 三选一 + 一句说明
4. 「发现的问题」：没问题写 **无**，没走这步写 **未验证** —— 这两个不一样
5. 「证据位置」留空，过振宇补
6. 记问题时注明是**角色无权**还是**状态不允许**

**结论写清范围**，例如：「**失败**，原型后台仍含「用户认证审核」流程，与需求「走学校统一身份认证、平台不审学生证」冲突」。

⚠️ **第 5 步要分开写**：

- 「页面上有没有置灰/提示」→ 页面层，能判通过/失败
- 「未认证用户真的拦住了」→ **未验证**，静态原型无身份与权限状态

不能合成一句"权限控制通过"。
