# V2.1 规则与状态实现基线

- 日期：2026-11-25
- 依据：`docs/requirements/SRS.md` V2.1 与当前后端实现
- 适用范围：规则与状态的实现口径

## 1. 文档边界

附件 PDF 是软件工程课程关于高质量编码、规则检查、状态检测和测试驱动开发的教学材料。它提供方法要求，不改变本项目的业务需求。项目业务规则以 SRS V2.1 为准。

## 2. 业务规则

| 编号 | 实现规则 | 状态结果 |
|---|---|---|
| BR-01 | 只有已认证且账号未封禁的学生可以发布商品和下单，不能购买自己的商品 | 拒绝时不新增记录、不改变商品 |
| BR-02 | 同一学生最多 5 件在售商品 | 超限拒绝，已有商品状态保持 |
| BR-03 | 信用分低于 60 禁止发布，低于 40 禁止下单 | 拒绝时状态保持 |
| BR-04 | 商品创建后进入待审核，管理员审核通过才进入在售 | 审核拒绝进入已下架并保留原因 |
| BR-05 | 商品只能从在售状态被下单，成交采用条件更新保证并发下只有一笔成功 | 成功时商品变为已售出并创建一笔有效成交 |
| BR-06 | 同一商品最多一笔有效成交，重复提交返回既有成交 | 不重复创建订单 |
| BR-07 | 成交金额等于下单时商品标价，平台不处理支付和交付事实 | 成交状态只记录有效或已撤销 |
| BR-08 | 撤销成交须由一方发起、另一方审批，评价产生后不可撤销 | 审批成功后成交变已撤销，商品按可交易性恢复在售或保持已下架 |
| BR-09 | 封禁账号不得新增发布、咨询和下单，既有成交记录保留 | 其在售商品联动下架 |
| BR-10 | 商品下架必须有原因，管理员处置须记录操作者、理由和审计信息 | 非法状态转换整体拒绝 |
| BR-11 | 每次信用分变化必须生成信用记录，分值保持在 0～150 | 超出边界按系统规则截断并留痕 |
| BR-12 | 通知由系统按业务事件生成，私信必须绑定具体商品且为纯文本单聊 | 通知和私信不改变成交状态 |

## 3. 状态集合

### 3.1 商品状态

`待审核`、`在售`、`已售出`、`已下架`

### 3.2 成交状态

`有效`、`已撤销`

成交记录不是支付、交付或退款状态机。平台不写入 `待支付`、`已支付`、`待交付`、`待确认`、`退款中`、`已退款` 等不可观测状态。

### 3.3 学生认证状态

`未提交`、`待审核`、`已认证`、`已驳回`

认证状态与账号状态分开。账号状态由 `正常`、`受限`、`封禁` 表示。

## 4. 合法转换

| 对象 | 当前状态 | 事件 | 结果 | 失败结果 |
|---|---|---|---|---|
| 商品 | 无 | 创建 | 待审核 | 不创建 |
| 商品 | 待审核 | 管理员通过 | 在售 | 保持待审核 |
| 商品 | 待审核/在售 | 审核拒绝或管理员下架 | 已下架 | 保持原状态 |
| 商品 | 在售 | 下单成功 | 已售出 | 保持在售，不创建成交 |
| 商品 | 已售出 | 双方审批撤销 | 在售或已下架 | 保持已售出 |
| 成交 | 无 | 下单成功 | 有效 | 不创建 |
| 成交 | 有效 | 撤销申请 | 有效并记录申请 | 保持有效 |
| 成交 | 有效 | 对方审批同意 | 已撤销 | 保持有效 |
| 成交 | 已撤销 | 再次下单或撤销 | 已撤销 | 拒绝并返回既有结果 |
| 认证 | 未提交/已驳回 | 提交申请 | 待审核 | 保持原状态 |
| 认证 | 待审核 | 管理员通过 | 已认证 | 保持待审核 |
| 认证 | 待审核 | 管理员驳回 | 已驳回 | 保持待审核 |

## 5. 实现检查点

- 商品下单使用 `WHERE status='在售'` 的条件更新。
- 有效成交使用唯一约束避免重复成交。
- 规则拒绝不产生订单、不改变商品状态。
- 状态字段使用常量闭集，数据库 CHECK 约束负责兜底。
- 订单、商品、通知和撤销回滚在同一事务内完成。
