### 3.2 SC-04 审核与重提怎么走

| 步 | 谁 | 做什么 | 预期 |
|---|---|---|---|
| 1 | 卖家 | 发布商品 | 状态 `待审核`，提示「等待管理员审核」 |
| 2 | 管理员 | 选不通过，原因填「禁售品类 A1：管制刀具」 | `已下架`，下架原因 `审核不通过`，驳回原因**含类目编号**，卖家收到通知 |
| 3 | 卖家 | 修改后重新提交 | 回到 `待审核`，**商品编号不变** |
| 4 | 管理员 | 通过 | `在售`，对外展示 |
| 5 | 卖家 | 另发一件，在 `待审核` 时点撤回 | `已下架`，下架原因 `卖家撤回`，**编号不变** |

**要专门试的四条**：

- 驳回时**不填原因 / 不引用类目编号** → 不允许提交结论，状态保持 `待审核`
- 下架原因是 `管理员违规下架` 或 `撤销后不可交易` 的商品点重提 → **拒绝**，提示联系管理员复核
- 非本人撤回、非 `待审核` 撤回 → 拒绝，状态保持
- 管理员审核一个 `已在售` 的商品 → **状态拒绝**，提示「当前业务状态不支持该操作」，不是权限拒绝

**18 类禁售清单怎么测**（SRS §4.3.1 要求逐类目构造 1 件、共 18 件）：

- 时间够：18 类各 1 件，全部应驳回且记录正确类目编号
- 时间不够：至少 **A1、A2、B2、C3、D1、E1 六类 + 2 条反向**；没打的类目在记录里写「未覆盖」，**不许报「全部通过」**
- 两条反向**必须放行**：二手 iPad（已恢复出厂、无账号）不得仅凭「二手」驳回；教材（含印制的习题答案）不得按 D2 驳回
- 清单外明显违规：SRS 要求标注「清单外待裁定」，但数据字典没有承载字段——**记「需求缺口 / 未验证」，不要自己定口径**

**并发对（§5.5 第 7 条，这三组归你，别跟吕锦浩/过振宇重复跑）**：

| 组 | 并发对 | 判据 |
|---|---|---|
| ② | 买家下单 vs 卖家主动下架 | 下单先成功则 `已售出`，下架被拒；下架先成功则 `已下架`，下单提示「该商品不可购买」 |
| ③ | 卖家编辑在售商品 vs 买家下单 | 下单先成功则编辑被拒；编辑先成功则商品回 `待审核`，下单被拒 |
| ⑥ | 管理员审核通过 vs 卖家撤回 | **先到者为准**（ST-02 或 ST-04），后到者按「当前业务状态不支持该操作」拒绝 |

**幂等类归你**：收藏（同一学生对同一商品只 1 条）、重复提交编辑（不得产生两份修改记录）。

### 3.3 SC-06 浏览与自助管理怎么走

| 步 | 操作 | 预期 |
|---|---|---|
| 1 | 搜索商品 | 结果**只含 `在售`**；待审核 / 已售出 / 已下架 / 已删除都不出现 |
| 2 | 按分类浏览 | 单层分类，**无二级下钻**；只列该分类下的在售商品；空分类要有空态（**具体文案 SRS 未规定，记实际值，不判逐字**） |
| 3 | 收藏一件在售商品 | 收藏成功，**商品不被锁定**，别人仍可下单 |
| 4 | 卖家把这件商品下架 | `已下架（卖家主动下架）`；买家收藏页显示「已失效」；**收藏记录不级联删除** |
| 5 | 卖家在「我的商品」看分组 | 四组：待审核 / 在售 / 已售出 / 已下架；每组按钮与状态匹配 |
| 6 | 在「我的订单」查看 | 只列本人作为买方或卖方的成交；已撤销只读、无评价入口 |
| 7 | 查看消息通知 | 倒序；点击置已读并跳转；未读数减 1 |

**补充项（UC-11 删除分支）**：

- `已下架` 商品可永久删除：从所有列表排除、不可恢复，**历史成交与收藏记录保留**
- `在售` / `待审核` / `已售出` 商品**不可删除**，必须先下架
- 已售出商品任何角色都不可下架、不可删除

**通知触发点（BR-15）抽查**：核验结果、商品审核通过/驳回、下单成交、收到新私信、对方撤销成交、撤销判定结果、卖家主动下架（通知收藏过的人）、商品重新回在售（通知收藏过的人）、违规下架、举报受理/处置、信用分变更。

### 3.4 SC-11 在售编辑与重审怎么走

| 步 | 操作 | 预期 |
|---|---|---|
| 1 | 卖家对 `在售` 商品改价格后提交 | 商品转 `待审核`（ST-12）；**下架原因清空**；**发布时间刷新**；**商品编号不变** |
| 2 | 立刻去搜索 / 分类看 | **立即消失**，重审通过前不可被下单 |
| 3 | 管理员在待审队列里通过 | 重新 `在售` |
| 4 | 编辑一件 `已售出` 商品 | 拒绝，提示「已售出商品不可修改」，原内容不变 |
| 5 | 尝试改发布人 / 商品状态 / 下架原因 / 发布时间 | 系统字段被丢弃或拒绝，其余字段照常保存 |

## 五、帽子三：兼容性 + 易用性

### 5.1 兼容性（课件讲三层：系统内部兼容、系统间兼容、系统自身兼容）

本项目是 Web 应用，没有外部系统对接，所以**系统间兼容**写「不涉及」并说明理由；重点做**浏览器与分辨率**：

| 维度 | 档位 | 检查点 |
|---|---|---|
| 浏览器 | Edge、Chrome（各 1 个版本，记版本号） | 首页 / 搜索 / 分类 / 详情 / 发布 / 我的商品 / 我的订单 / 通知 / 管理端 7 页 |
| 分辨率 | 1366×768、1920×1080 | 布局不溢出、按钮可点、表格不横向截断 |
| 控制台 | 两个浏览器 | **0 报错**（有警告要记录并说明） |
| 图片上传 | 大图、长图 | 能上传、能预览、不崩 |

判据不是「我觉得挺好看」，而是**同一操作在两种环境下结果一致**。

### 5.2 易用性（用课件「十大交互原则」逐条打分）

| 原则 | 在本项目看哪里 | 判据 |
|---|---|---|
| 状态可见 | 发布后是否明确告知「等待审核」；下架/驳回是否说明原因 | 每个操作都有明确反馈 |
| 环境贴切 | 「立即购买」「联系卖家」的位置与文案 | 符合二手交易直觉 |
| 用户可控 | 编辑未提交能否取消；发布前能否回退 | 有撤销/返回路径 |
| 一致性 | 「商品/物品」「消息通知/私信」是否混用 | 与术语表一致 |
| 防错 | 价格、图片数量、在售上限的**就地提示** | 提交前拦住，而不是提交后报错 |
| 易取 | 我的商品/订单入口是否好找 | 两步内可达 |
| 灵活高效 | 搜索、分类筛选是否顺手 | 常用操作不绕路 |
| 优美简约 | 列表/详情信息密度 | 无冗余信息干扰 |
| 容错 | 报错是否说清「怎么改」 | 不用代码式提示 |
| 人性化帮助 | 认证、发布是否有引导 | 新用户能自己走通 |

## 六、你这块最容易漏的 8 个点

1. **二手 iPad 必须放行**：SRS §4.3.2 第 3 条，不得仅凭「二手」驳回。
2. **教材含印制答案必须放行**：正常习题与答案不属 D2。
3. **清单外没有承载字段**：要求标注「清单外待裁定」，但下架原因是五值封闭集——记需求缺口，别自己造字段。
4. **价格边界**：0 与 50000.01 拒、50000 通过、最多 2 位小数。
5. **图片数量**：0 张拒、10 张拒、9 张通过。
6. **在售上限只数「在售」**：待审核 / 已售出 / 已下架不计入 5 件。
7. **编辑后立即从列表移除**：不是「下次刷新才消失」。
8. **删除只限已下架**：软删除，历史成交与收藏保留，不可恢复。

## 九、三条硬规矩

1. **失败样本不许删**。只交「全绿」等于没测；加载超 2 秒的样本正是 NFR-01 要的。
2. **同一场景至少换一组数据再跑一遍**。课件讲「杀虫剂悖论」：同一批用例跑多了会免疫。
