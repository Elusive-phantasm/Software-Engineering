### 3.3 SC-02 权限面怎么打（这是本模块最值钱的一项）

**① 提示语逐字比对**（SRS §5.2 原文，差一个字就算 BUG）：

| 场景 | 期望提示语 |
|---|---|
| 游客发布 / 下单 | 请先登录并完成学生证核验 |
| 未提交学生证 | 请先上传学生证 |
| 待审核 | 核验审核中，请等待 |
| 已驳回 | 核验未通过，请按原因修改后重新提交 |
| 管理员发布 / 下单 / 评价 | 管理员无发布商品权限 / 管理员无下单权限 / 管理员无评价权限 |
| 管理员提交举报 | 管理员不能以举报人身份提交举报 |
| 账号封禁 | 账号已封禁，不可发布与下单 |
| 信用分不足 | 信用分不足，暂不可发布新商品 / 信用分不足，暂不可下单 |
| 商品状态不符 | 该商品不可购买（**状态拒绝，不是权限拒绝**） |

> ⚠️ **SRS 内部有一处冲突**：UC-05 辅C 写「请先完成学生证核验」，§5.2 写「请先上传学生证」。**以 §5.2 为准**，把差异记成「需求冲突」，不要当 BUG 报给赵俊豪。

**② 权限矩阵抽样**（每格至少一条请求，别只点界面按钮——用接口直接打，绕过前端隐藏）：

| 操作 | 游客 | 未认证学生 | 已认证学生 | 管理员 |
|---|---|---|---|---|
| 发布商品 | 拒绝 | 拒绝 | 允许 | 拒绝 |
| 下单成交 | 拒绝 | 拒绝 | 允许 | 拒绝 |
| 收藏商品 | 拒绝 | 允许 | 允许 | 拒绝 |
| 评价 / 举报 | 拒绝 | 拒绝 | 允许 | 拒绝 |
| 发送私信 | 拒绝 | 拒绝 | 允许（限本人参与） | 拒绝 |
| 撤销成交 / 编辑商品 | 拒绝 | 拒绝 | 允许（限本人） | 拒绝 |
| 审核商品 / 核验 / 下架 / 扣分 | 拒绝 | 拒绝 | 拒绝 | 允许 |

**③ 拒绝之后要查四样**（SRS §5.5 第 2、3 条）：

- 业务数据不变：商品、成交、评价、举报、信用记录都没新增
- 状态不变：商品状态、认证状态、账号状态原地不动
- **信用分不变**：权限拒绝不扣分（这是最容易写错的一条）
- 审计里**没有**密码、完整手机号、完整宿舍地址、学生证图片内容

**④ 权限拒绝 vs 状态拒绝要分得开**：角色无权用 §5.2 的话术；角色有权但状态不满足，提示「当前业务状态不支持该操作」（对已售出商品下单是这一类）。

### 3.4 SC-08 核验异常怎么走

| 步 | 操作 | 预期 |
|---|---|---|
| 1 | 认证 `未提交` 时尝试发布 / 下单 | 被拒，提示「请先上传学生证」；不生成商品/订单 |
| 2 | 提交核验后（`待审核`）再试 | 被拒，提示「核验审核中，请等待」 |
| 3 | 管理员驳回，不填驳回原因 | **驳回原因为空时不允许提交结论**；状态保持 `待审核` |
| 4 | 管理员正式驳回 | 状态转 `已驳回`；重提次数 +1；学生收到含原因的通知 |
| 5 | 学生修改后重提（未达 3 次） | 转 `待审核`；重提次数再 +1；超过 3 次保持 `已驳回` 并提示联系管理员 |
| 6 | 提交满 24 小时不审核 | **状态保持 `待审核`**，只提醒，**不得自动通过** |
| 7 | 注册满 7 天仍未提交核验 | **状态保持 `未提交`**，每日提醒一次；**不得自动驳回、不得封禁** |
| 8 | 事后核实证件伪造 | 认证转 `已驳回` **且同一动作内封禁账号**；只改认证不封禁算 BUG |

> AT-08 的「封禁」在你这里判；封禁后商品是否联动下架，**归过振宇的 SC-12**，别重复记录，但要互相核对结论一致。

### 3.5 NFR-05 登录安全怎么测

用专用测试账号（建议用 `lv@campus.edu` 或自己注册一个，别把 `lin` 锁死）：

- 第 1～4 次错密码：**不锁**，提示凭据错误
- 第 5 次错：记下触发时刻 `t`，提示「账号已暂时锁定，请稍后重试」
- `[t, t+15 分钟)` 内：**即使密码正确也拒绝**，且**不延长**锁定截止时间
- `t+15 分钟` 整：允许重新验证（**左闭右开**，正好到点算解锁）
- 换浏览器 / 换设备：同一账号共用一份计数，**不能各自重新累计**
- 成功登录后：失败计数清零
- 锁定期间：认证状态、商品状态、信用分、账号封禁状态**都不许变**

### 3.6 NFR-08 学生证信息安全怎么测

四个身份交叉：**本人 / 其他已认证学生 / 非审核管理员 / 游客**。

| 检查点 | 期望 |
|---|---|
| 用申请编号换别人的学生证图片 | 403，响应体**不含 base64**、不含文件名 |
| 公开页面、通知、导出里出现学生证 | 0 次 |
| 日志 / 审计正文出现图片内容 | 0 次 |
| 明文直链可直接打开图片 | 0 条 |
| 密码回显、明文存储 | 0 次 |

⚠️ SRS 写明「认证申请留存期限待确认」——**这一项只能判「范围已覆盖、期限待确认」，不能宣称合规**。

### 3.7 NFR-10 验证码怎么测

| 点 | 判据 |
|---|---|
| 格式 | 6 位数字 |
| 有效期 | 10 分钟（未满 10 分钟可用，整 10 分钟即失效） |
| 一次性 | 验证通过后立即作废，重放失败 |
| 错误次数 | 同一码错 5 次作废，第 6 次用对的也失败 |
| 频控 | 同一邮箱 60 秒内 1 次、24 小时内 10 次，超出返回明确失败 |
| 防枚举 | 找回密码对「邮箱存在/不存在」返回**同一句提示**；两组各 20 次，均值差**不得构成可判定信号** |
| 会话失效 | 改密成功后旧令牌全部 401 |
| 明文 | 存储为哈希；日志/审计/导出/错误提示里 0 次 |
| 封禁账号 | 可重置密码，但登录仍被拒 |

> 「响应时间差 ≤100 毫秒」是 SRS 写的**建议值，待确认**。我们能给的结论是「未发现显著差异」，**不能写「已达标」**。

## 五、帽子三：信息安全测试专项

课件把 Web 信息安全测试分成十几类，我们只做**能在这个项目里打到的**，其余写「不在范围」并说明理由。

| 课件类别 | 本项目怎么打 | 判据 |
|---|---|---|

## 六、你这块最容易漏的 6 个点

1. **提示语三态不能混**：未提交 / 待审核 / 已驳回是**三句不同的话**（§5.2），最容易统一写成「请先完成核验」。
2. **管理员不是学生**：管理员不因身份获得发布、下单、评价、举报、私信权限；也不能被当成「已认证学生」。
3. **锁定和封禁不改变认证状态与信用分**：§5.5 第 6 条 + BR-19，登录保护只改计数与截止时间。
4. **封禁账号仍可浏览、提交举报、重置密码**，只是登录被拒（BR-10、NFR-10）——别一封了之。
5. **学生证图片只有审核管理员能读**：游客、其他学生、非审核管理员请求都要 403，且响应体不能带 base64。
6. **一个建议值别当已确认**：防枚举的「响应时间差 ≤100 毫秒」是建议值，只能写「未发现显著差异」；而「60 秒 1 次 / 24 小时 10 次」「错 5 次作废」是硬要求，必须判。

## 九、三条硬规矩

1. **失败样本不许删**。只交「全绿」等于没测；超时、报错、状态不对都要留。
2. **同一场景至少换一组数据再跑一遍**。课件讲「杀虫剂悖论」：同一批用例跑多了会免疫，第二遍要换边界值。
3. **测试只能证明有缺陷，不能证明没缺陷**。你的结论写「未发现与预期不符」，不写「功能正确」。
