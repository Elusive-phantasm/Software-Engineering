## 四、原型怎么做

用 **Figma** 或 **墨刀**（都是网页免费版）做几张**能点开的假界面**：

1. 首页（商品列表）
2. 商品详情页
3. 下单页
4. 后台审核页

不用做得很精细，能点、能看出流程就行。

⚠️ **老师原话：「可点击界面不等于后台业务已经实现」。**

意思是：你做了个能点的下单页，**不代表下单功能真的做出来了**。
所以你的结论只能写「页面流程没问题」，**不能写成「功能验证通过」**。

结论只能从这三个里选：**通过 / 失败 / 未验证**，而且要写清验证范围，比如：

> ✅ 通过，页面流程走查
> ❌ 不能写：通过，验证了下单功能

## 五、走查记录怎么写

就是**照着流程演一遍，把发现的问题记下来**。

### 5.1 表格格式（每个场景一张）

| 步骤 | 谁 | 做什么 | 系统应该怎样 | 发现的问题 |
|---|---|---|---|---|
| 1 | 学生 | 点「立即购买」 | 进入下单页 | 无 |
| 2 | 学生 | 提交订单 | 生成订单，商品变「已预订」 | 无 |
| 3 | 另一个学生 | 同时点「立即购买」 | 应该提示「已被预订」 | ⚠️ 这种情况没规定 |

第 3 步那个 ⚠️ 就是「发现的问题」，记成 `V-01`，发给我，
我转给吕锦浩让他补规则、改状态表。

### 5.2 至少要走 4 类场景

| 场景类型 | 具体走什么 | 编号 |
|---|---|---|
| **正常主流程** | 发布 → 浏览 → 下单 → 付款 → 交付 → 确认 → 评价 | SC-01 |
| **权限流程** | 未实名用户想发布商品，应该被拒绝；被拒绝时提示清不清楚、数据有没有乱变 | SC-02 |
| **状态转换流程** | 订单超时自动取消后，商品是不是真的回到「在售」 | SC-03 |
| **异常流程** | 已付款但卖家不交付、买家举报、商品被下架 | SC-04 |

### 5.3 每个场景还要写一小段「基本信息」

放在表格前面就行：

- 走查编号：SC-01
- 场景名称及类型：正常借出流程 / 正常主流程
- 任务目标与情境：（一句话）
- 初始数据与状态：（比如「商品在售、买家已实名、买家没买过这件」）
- 走查方式：本组自走查 / 交叉走查 / AI 反向走查
- 走查依据及版本：需求文档 v1.0
- 参与者姓名、分工、日期：
- 关联的需求、规则编号：UC-06、BR-01、ST-01

⚠️ **「无」和「未验证」不一样**：
- 走查了、没发现问题 → 写 **无**
- 根本没走查 → 写 **未验证**

老师明确说了：**没做检查不能写成「未发现问题」**。
