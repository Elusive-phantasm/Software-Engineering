# 分阶段实现与测试计划

> **依据**：SRS V2.1、ADR-006、Q-01～Q-06、模板 F/G/E/H/I。
> **原则**：不要把全部接口一次性细化；跨模块契约与当前阶段依赖必须先确认（见《接口与关键设计说明书》）。
> **声明**：本计划由 AI 起草，阶段准入与验收须由组长、审查人签字。

## 1 阶段总表（模板 F）

| 阶段 | 可运行业务链 | 需求范围 | 前置 Q/ADR | 接口 | 必测风险 | 退出条件 |
|---|---|---|---|---|---|---|
| **S1** 身份与商品 | 注册登录 → 提交核验 → 管理员审核 → 发布商品 → 管理员审核 → 搜索可见 | UC-01、02、03、04、05、06、07、08、11、17、32、34；AT-01～05、ST-01～04、06、08、12 | Q-01、Q-02、Q-03；ADR-001、002、003、005 | API-02、API-03、API-11、API-13、API-18、API-19、API-28、API-29 + 撤回/下架/删除/重提（API-20～23） | ① 未认证越权发布；② 审核驳回不引用类目编号；③ 价格/图片边界；④ 在售 5 件上限；⑤ 编辑回待审核后仍可被下单 | 主链可演示；TC-001～028 结论已记录；冒烟与边界测试通过；交叉审查完成；无阻塞 Q |
| **S2** 交易与信用 | 搜索 → 下单成交 → 撤销或判责 → 评价 → 信用分变化 | UC-09、10、14、15、16、31；BR-06、08、13、14、21；ST-05、10、11 | Q-04、Q-05；ADR-004 | 下单、撤销、判定、评价、收藏、信用查询 | ① 并发下单重复成交；② 撤销与评价互斥；③ 7 天扣分重复触发；④ 信用分截断越界；⑤ 权限拒绝误扣分 | 交易链可演示；TC-029～042 通过；并发脚本通过；S1 回归通过 |
| **S3** 治理与沟通 | 举报 → 处置/封禁联动 → 私信沟通 → 通知与主页 | UC-12、13、18、29、30、33；BR-04、10、15、18、20；ST-07、09、13 | Q-06；ADR-005 | 举报、处置、私信、通知、主页 | ① 封禁只封不禁；② 已售出商品被误下架；③ 私信越权读取；④ 管理员读学生会话；⑤ 通知消息类型不符 | 治理链可演示；TC-043～056 通过；权限与隐私扫描通过；S1/S2 回归通过 |

**阶段划分依据**：依赖顺序（无商品不能下单、无下单不能评价与撤销、治理依赖用户与商品）；每阶段都能单独演示一条完整业务链。

- [ ] 阻塞本阶段的 Q 已关闭，相关 ADR 已接受。

- [ ] 数据不变量、事务和权限边界明确（《接口与关键设计说明书》§3）。
- [ ] 测试预期已人工核验，必要测试数据可用（TC 表 + 种子账号）。

## 7 测试时间安排（速查）

| 时点 | 做什么 | 产出 |
|---|---|---|
| 架构确认时 | 状态/权限/事务场景走查 | Q/ADR 验证记录 |
| 当前任务编码前 | 独立确认测试预期与数据 | 测试案例（TC/BB） |
| 编码过程中 | 接口、数据库集成 | 脚本与原始输出 |
| 每次合并前 | diff 审查 + 受影响回归 | 审查记录 |
| 每阶段完成 | 纵向链路、异常、跨模块 | 阶段验收单 |
| 最终部署后 | 系统、性能、安全边界、恢复 | 最终测试与部署证据 |

## 8 证据归集要求

- 目录：`evidence/`，命名 `S<阶段>-<任务>-<场景>-<日期>.<扩展名>`，例：`S1-TASK-03-price-boundary-20261112.log`。
- 必存：脚本原始输出（含失败样本）、数据库查询结果、关键页面截图（文件名与记录一致）、审查记录。
- 禁止：只交「全绿」摘要、删改失败样本、用截图替代可复现命令。
