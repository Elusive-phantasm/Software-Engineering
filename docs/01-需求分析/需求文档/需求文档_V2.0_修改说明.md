## 2. 修改动因（两条团队裁定）

### 2.1 学校不提供代收点、回收人员、仓库

捐赠需要**实物归集与保管**，回收需要**接收方与处理渠道**，两者都依赖平台不具备的物理节点。原设计的
「送到代收点 / 等待工作人员上门收取」「领取人凭预约到代收点取件」「管理员确认入库 / 确认回收完成」
全部建立在并不存在的物理设施上。

**裁定**：捐赠、回收、借用三条物品流转路径**整体删除**，不保留空壳编号。

### 2.2 状态机过于复杂

原交易链为：下单 → 标记已付款 → 卖家确认收款 → 约见面 → 交付记录 → 确认收货 → 评价，
承接 8 个订单状态、5 个商品状态、16 个物品流转转换。

**裁定**：交易链压缩为 **发布 → 审核 → 在售 → 下单成交**，**没有支付、没有交付确认**。

## 3. 删除内容清单

### 3.1 整条流程删除

| 删除项 | 原位置 | 删除理由 |
|---|---|---|
| 完成支付（标记已付款 / 卖家确认收款） | UC-07、BR-10、ST-02、ST-03 | 平台不碰钱，无权也无能力判定「钱是否到账」，该状态**无法被验证** |
| 约定见面交付、交付记录 | UC-08、BR-11、ST-04、ST-05 | 交付全程线下，平台**无任何观测点**，强行记录只能得到不可信的自述数据 |
| 确认收货、自动确认收货 | UC-10、BR-14、ST-06、ST-34 | 无交付确认则无收货时点，前置条件不成立 |
| 取消订单、退款中、已退款 | UC-20、BR-12、BR-13、ST-08～ST-10、ST-31～ST-33 | 依赖已付款事实；本版不存在付款事实，**无款可退** |
| 支付超时自动取消 | BR-03、ST-07 | 同上 |
| 人工处置标记 | BR-23、ST-12 | 该标记用于「已付款订单被违规下架时冻结订单」，本版无未结束订单可标记 |
| 捐赠 / 回收 / 借用三条流转 | UC-17～UC-19、UC-24、UC-25、BR-20、SM-03、FT-01～FT-16 | 见 §2.1，物理节点不存在 |
| 申诉流程与申诉状态 | UC-15 主事件流第 5 步、附事件流 C/D/E | 本期精简；卖家的异议改为在站内消息中提出，由管理员人工复核，不设申诉实体与申诉状态 |
| NFR-05 支付信息安全 | §8.6 | 平台已定案不涉及任何资金与支付信息，转为 §2.1 边界声明与 §5.5 审计禁令 |
| 成功指标「流程无保障」对应问题 P-03 | §1.2 | 平台只做撮合与成交登记，不宣称解决该问题，避免把「不做的部分」说成「已解决」 |

### 3.2 状态机收缩

| 状态机 | V1.2.1 | V2.0 | 说明 |
|---|---|---|---|
| 订单状态机 SM-01 | 8 状态：待支付、已支付、待交付、待确认、已完成、已取消、退款中、已退款 | **整体取消** | 订单改为成交记录，无状态字段，创建即终态 |
| 商品状态机 | 5 状态：待审核、在售、**已预订**、已售出、已下架 | **4 状态**：待审核、在售、已售出、已下架 | 删除「已预订」：下单即成交，不存在「被占用但未成交」的锁定等待期 |
| 物品流转 SM-03 | 捐赠 5 态 + 借用 5 态 + 回收 4 态，FT-01～FT-16 | **整体删除** | 见 §2.1 |
| 认证状态 SM-02 | 4 态，AT-01～AT-08 | **原样保留** | 与交易链无关，且是 G-01「让交易可信」的支撑 |
| 账号状态 | 术语表有定义，数据字典**缺字段** | 保留并**补入数据字典** | 见 §4.2 |
