# 1 业务目标

## 1.1 项目愿景

在校内建立一个**可信、便捷的**闲置物品交易与流转平台，让学生手中闲置的教材、数码产品、生活用品，能够安全地在同校同学之间流转，减少资源浪费。

## 1.2 现状问题

| 编号 | 问题 | 具体表现 |
|---|---|---|
| P-01 | **信息分散** | 闲置信息散落在各类社交群与二手论坛，缺乏统一入口，商品状态不透明 |
| P-02 | **信任缺失** | 交易双方互不了解身份，无法判断对方是否为同校学生，也无法评估历史交易表现 |
| P-03 | **流程无保障** | 交易全程无记录，交付安排、付款确认、收货确认靠口头约定，纠纷时无据可查 |
| P-04 | **违规无人管** | 违禁品、虚假描述商品缺乏审核与事后处置机制 |

## 1.3 业务目标分解

| 编号 | 目标 | 达成方式 |
|---|---|---|
| **G-01** | 让交易可信 | 校内统一身份认证准入 · 双向交易评价 · 信用分机制 · 违规商品举报与处置 |
| **G-02** | 让交易便捷 | 商品快速发布 · 关键词搜索与分类浏览 · 两条交付路径 · 订单状态全程可视 |
| **G-03** | 让闲置物品流转起来 | 除买卖之外，提供**捐赠、回收、借用**三条流转路径 |

> 目标分解类型为**「与」分解（AND）**：三个子目标须同时满足，缺任一则总体目标不成立。

## 1.4 主要成功指标

| 编号 | 指标 | 目标值 | 来源性质 | 确认状态 |
|---|---|---|---|---|
| M-01 | 完成认证的学生数 | 首学期 500 人 | 分析推导 | 待确认 |
| M-02 | 每月成功交易笔数 | 300 笔 / 月 | 分析推导 | 待确认 |
| M-03 | 违规商品平均处置时长 | 24 小时内 | 分析推导 | 待确认 |

# 2 范围

## 2.1 系统边界声明

本平台是一套**校内专用**的二手交易与物品流转系统。以下四条边界为**组内定案**，全文所有需求均以此为前提：

| 边界项 | 声明 |
|---|---|
| **资金** | **平台不托管资金**。资金由买卖双方通过第三方支付（微信 / 支付宝）**直接结算**；平台只记录订单状态与交易参考信息（时间、金额、订单号、付款参考号），**禁止存储**支付密码、卡号、验证码 |
| **身份** | **平台不自建账号体系**。平台调用**学校统一身份认证**核验学生身份并取得学号，不接触学生密码；「注册」流程不存在，首次登录自动建档 |
| **交付** | **平台不提供物流**。交付全部在线下完成，仅支持 `见面交付` 与 `自提点` 两种方式 |
| **退款** | **退款不是平台功能**，只是订单状态变化。实际退款由买卖双方线下完成，平台仅记录 `退款中` → `已退款` |

> 上述边界直接决定了 §7 的订单状态机形态：因平台拿不到支付回调，`已支付` 必须由**卖家确认收款**判定，而非系统自动判定。

## 2.2 目标范围

### 2.2.1 目标内

| 范围块 | 内容 |
|---|---|
| 交易 | 商品发布、审核、搜索、分类浏览、收藏、下单、支付确认、交付、确认收货、双向评价 |
| 治理 | 违规商品举报、管理员巡查、违规处置、信用分 |
| 流转 | 捐赠、回收、借用三条路径及其状态流转 |
| 支撑 | 订单查询、商品查询、消息通知 |

### 2.2.2 目标外

| 不在范围内 | 原因 |
|---|---|
| 平台代收代付、资金池、担保交易 | 需支付牌照与商户资质，本项目不具备 |
| 物流配送、快递对接 | 交付全程线下完成 |
| 跨校交易 | 仅限本校学生 |
| 议价 / 竞价 | 平台不做议价，下单即以标价成交 |
| 商品推荐算法、广告位 | 非本期目标 |
| 账号注销 | 平台不自建账号体系，账号生命周期由学校统一身份认证管理；平台侧仅处理「受限 / 封禁」状态 |

## 3.2 用例说明（UC-01 ~ UC-25）


### UC-01 通过统一身份认证登录并核验身份

| 字段 | 内容 |
|---|---|
| 参与者 | 学生 |
| 目标 | 进入平台并完成学号身份核验 |
| 前置条件 | 已通过学校统一身份认证登录 |
| 触发条件 | 学生点击「登录」 |
| 主事件流 | 1. 学生点击「登录」<br>2. 系统跳转学校统一身份认证<br>3. 学生在学校认证页完成认证<br>4. 系统接收学校返回的学号与身份信息<br>5. 首次登录自动建档<br>6. 账号状态标记为「已认证」，可发布与购买 |
| 辅事件流 | A. 学校认证未通过或学生取消 → 返回登录页，账号保持「未认证」<br>B. 学校返回的学号已绑定其他账号 → 提示「该学号已绑定其他账号」，转身份核验申诉由管理员人工处理，账号保持「未认证」<br>C. 未认证学生尝试发布/下单/评价 → 拦截并提示「请先登录并通过身份核验」，账号保持「未认证」（UC-02、UC-06、UC-11 引用此流）<br>D. 学生在校信息变更（转专业、换院系）→ 以学校返回信息为准，下次登录自动更新，无需重新认证<br>E. 统一身份认证服务不可用 → 提示「认证服务暂不可用，请稍后再试」，账号保持「未认证」 |
| 后置条件 | 账号状态为「已认证」，可发布和购买；认证记录留档 |
| 发生频率 | 上课日 9:00–23:00 约 1200 次/天（含既有账号每次登录） |
| 关联 | BR-待定（一学号一账号）、NFR（单点登录响应时间、个人信息保护） |

### UC-02 发布二手物品

| 字段 | 内容 |
|---|---|
| 参与者 | 学生（卖家） |
| 目标 | 卖家把要卖的物品或要出借的物品挂到平台，审核通过后对外展示 |
| 前置条件 | 已登录、已认证；账号未被限制发布 |
| 触发条件 | 卖家在「我要卖」页点击「发布」 |
| 主事件流 | 1. 选择发布类型（出售 / 出借）<br>2. 填写标题、分类、价格或押金、成色、描述<br>3. 上传物品图片（1–9 张）<br>4. 选择可交付方式（见面交付 / 送到自提点）<br>5. 提交<br>6. 系统生成一条「待审核」商品，提示「等待管理员审核」 |
| 辅事件流 | A. 必填项缺失或价格非法（≤0、超过上限）→ 就地提示，**不生成商品**，页面保持编辑中<br>B. 图片格式/大小不符，或含水印联系方式 → 提示重新上传，**不生成商品**（是否禁止联系方式由 BR 定）<br>C. 未认证 → 走 UC-01 辅事件流 C，**不生成商品**<br>D. 与已有商品高度重复（同图同描述）→ 提示「疑似重复发布」转人工复核，**商品保持「待审核」**<br>E. 卖家在待审核期间想改 → 可撤回后重新提交（沿用原商品编号，是否计入发布次数由 BR 定）<br>F. 发布类型选了「出借」但未填可借时段、押金或归还要求 → 提示补全，**不生成商品** |
| 后置条件 | 生成一条「待审核」商品；此时不对外展示 |
| 发生频率 | 上课日 9:00–23:00 约 260 次/天，开学季 800 次/天 |
| 关联 | BR-待定（价格上限、违禁品清单、图片张数）、ST（待审核 → 在售 / 已下架）、UC-14、UC-19、UC-22 |

### UC-03 搜索商品

| 字段 | 内容 |
|---|---|
| 参与者 | 学生 |
| 目标 | 快速找到想买的商品 |
| 前置条件 | 无（未登录可浏览；下单才需要登录与认证） |
| 触发条件 | 在首页搜索框输入关键词并搜索，或提交筛选条件 |
| 主事件流 | 1. 输入关键词，或选择筛选条件（分类、价格区间、成色、交付方式、排序）<br>2. 系统检索处于「在售」的商品<br>3. 返回结果列表（图片、标题、价格、成色、发布时间）<br>4. 学生点击进入商品详情页 |
| 辅事件流 | A. 无匹配结果 → 提示「没有找到相关商品」，推荐相邻分类或建议放宽筛选，列表为空<br>B. 关键词为空 → 提示先输入关键词，**不发起检索**<br>C. 结果中混入已售出/已下架商品 → 不展示<br>D. 浏览期间商品被他人下单 → 详情页提示「该商品已被预订」，购买按钮置灰，**商品状态不变**<br>E. 关键词为敏感词/违规内容 → 按 BR 过滤并提示，**不发起检索** |
| 后置条件 | 无（只读操作） |
| 发生频率 | 上课日约 6000 次/天（人均约 15 次） |
| 关联 | BR-待定（只展示在售、排序规则） |

### UC-04 按分类浏览商品

| 字段 | 内容 |
|---|---|
| 参与者 | 学生 |
| 目标 | 按分类逐层浏览，发现想买的商品 |
| 前置条件 | 无（未登录可浏览） |
| 触发条件 | 在首页点击分类入口 |
| 主事件流 | 1. 系统展示一级分类列表<br>2. 学生选择分类（教材书籍、电子数码、生活用品、代步工具等）<br>3. 系统列出该分类下「在售」商品<br>4. 可继续下钻子分类或切换排序 |
| 辅事件流 | A. 该分类下无商品 → 展示「该分类暂无商品」，推荐相邻分类<br>B. 分类入口被停用或合并 → 该入口不再展示<br>C. 分类与商品不符 → 学生可举报该商品（UC-12） |
| 后置条件 | 无（只读操作） |
| 发生频率 | 上课日约 3000 次/天 |
| 关联 | BR-待定（分类目录、只展示在售） |

### UC-05 收藏商品

| 字段 | 内容 |
|---|---|
| 参与者 | 学生 |
| 目标 | 把感兴趣的商品存起来，之后再决定是否购买 |
| 前置条件 | 已登录 |
| 触发条件 | 在商品详情页或列表页点击「收藏」 |
| 主事件流 | 1. 点击「收藏」<br>2. 系统把商品加入个人收藏夹并提示「已收藏」<br>3. 学生可在「我的收藏」查看、取消收藏、进入商品详情 |
| 辅事件流 | A. 重复收藏 → 提示「已收藏」，**不重复记录**<br>B. 收藏后商品被卖出或下架 → 收藏列表标记「已失效」，不可下单，**商品状态不变**<br>C. 未登录点击收藏 → 引导登录，**不生成收藏记录**<br>D. 收藏数量达到上限 → 提示先清理收藏（上限由 BR 定），**不新增收藏** |
| 后置条件 | 收藏关系已记录 |
| 发生频率 | 上课日约 400 次/天 |
| 关联 | BR-待定（收藏上限） |

### UC-06 下单

| 字段 | 内容 |
|---|---|
| 参与者 | 学生（买家） |
| 目标 | 买家锁定想要的商品并生成订单 |
| 前置条件 | 已登录、已认证、商品处于「在售」、不是自己发布的 |
| 触发条件 | 买家在商品详情页点击「立即购买」 |
| 主事件流 | 1. 点击「立即购买」<br>2. 系统检查商品状态与买家资格<br>3. 选择交付方式（见面交付 / 送到自提点）<br>4. 确认订单信息并提交<br>5. 系统锁定商品并生成订单 |

### UC-15 处理举报、申诉与违规处置

| 字段 | 内容 |
|---|---|

# 5 权限需求

## 5.1 角色及判定口径


游客为未登录访问者；未认证学生、已认证学生为已登录且处于对应认证状态的学生；管理员是独立管理角色。四类角色及基础权限矩阵按已定案规则维护，不把管理员自动视为已认证学生。一个自然人若同时拥有学生和管理员身份，如何切换角色待确认；当前按本次操作的有效角色判定，禁止借管理员身份发布、下单或评价。

“允许”仅表示通过角色权限条件，仍需通过对象归属、数据可见范围及正式业务状态条件；“拒绝”表示基础角色无权。未认证学生浏览权限不因认证状态而被收回；锁定登录规则不擅自改变浏览或认证状态。

## 5.5 权限控制业务规则


1. **角色与对象校验**：每次实际操作都检查有效身份、角色、对象归属和字段可见范围。隐藏按钮只能辅助交互；直接指定他人编号、换入口或重复提交也必须受同样限制。默认不返回拒绝访问对象的手机号、地址、信用分或举报人身份。
2. **权限拒绝不改变业务**：被拒绝时不创建商品、订单、评价、举报或信用记录，不变更商品、订单、举报处理状态，不删除评价，不更新信用分；不得因一次被拒绝操作扣信用分。允许追加必要的安全审计记录，审计记录不算业务实体变动。
3. **权限拒绝与状态拒绝区分**：角色无权时使用矩阵中的身份或权限提示；角色有权但状态不满足时提示“当前业务状态不支持该操作”，并说明可安全公开的原因。两类拒绝均保持本次操作前的业务数据与状态不变，审计原因分别记录。正式状态规则未到位前，不擅自确定“哪个状态允许哪一步”。
4. **拒绝提示要准确**：未认证学生发布时提示认证，不能误报系统故障；管理员下单时提示角色无权，不能诱导管理员完成学生认证来绕过限制；普通学生查看他人信用分时允许返回分数，但不得展示信用变动明细；查看他人信用变动明细时应提示无权。
5. **必要审计**：记录权限拒绝、敏感个人信息读取和管理员审核／下架／删除等管理操作。审计至少含操作时间、操作者可得标识（游客使用会话标识）、有效角色、动作、目标可得标识、结果和原因类别；不得写入支付密码、登录密码、完整手机号或完整宿舍地址。保留期限、审计访问权限待确认；不新增独立审计管理功能或审计实体设计。
6. **登录失败是独立安全行为**：原文连续失败 5 次锁定 15 分钟会改变登录失败计数和锁定截止时间，并可追加安全日志；这些不属于“发布／下单被拒绝”导致的业务状态变化。不得顺带变更认证状态、商品状态、订单状态或信用分。
7. **在业务状态并发变化时**：候选要求为以提交执行时检查到的合法条件为准；若其他操作已使商品不可下单，应拒绝本次操作，不留下本次新订单或错误预订状态。如何识别唯一有效订单须由业务规则负责人确认；本次无权要求覆盖其他合法操作的结果。
8. **允许操作的影响不混同于拒绝**：管理员审核、下架和删除成功后的状态、历史保留及关联影响须与正式规则对齐；本文件不擅自指定自动取消订单或扣分。举报提交成功本身不等于违规已经成立；是否触发自动下架或其他处置缺少正式定义，待确认，本文件不预设自动处置规则。

| 未认证学生尝试下单 | 请先完成学生认证；权限拒绝 | 不新增订单；商品不变成已预订 | 权限拒绝；不记录敏感明文 |
| 已认证学生指定他人学号读取手机号 | 仅本人或具备相应管理权限的管理员可查看 | 不返回手机号；本人、目标学生及业务对象均不变 | 拒绝及目标标识；不含真实手机号 |
| 管理员尝试下单或评价 | 管理员无下单权限／管理员无评价权限 | 无新增订单／评价；不改变商品或信用分 | 权限拒绝；角色为管理员 |
| 已认证学生删除他人评价 | 仅管理员可删除他人评价 | 原评价保留；信用分不变 | 权限拒绝 |
| 已认证学生查看交易对方信用分 | 允许，仅显示分数 | 返回分数，不返回信用变动明细 | 访问结果可追溯；不改变分数与信用记录 |
| 管理员提交举报 | 管理员不能以举报人身份提交举报 | 不新增举报记录 | 权限拒绝 |
| 已认证学生下单时商品不满足正式可下单状态条件 | 当前业务状态不支持该操作；状态拒绝 | 不产生本次订单；无本次错误状态变更 | 业务状态拒绝，不误记角色无权 |
| 管理员审核状态不允许审核的商品 | 当前业务状态不支持该操作；状态拒绝 | 商品原状态及订单不变 | 业务状态拒绝 |
| 管理员巡查发现违规商品 | 管理员按职责进入审核或处置流程 | 不创建举报记录；后续处置按正式规则执行 | 管理操作可追溯 |
| 已认证学生查看本人信用记录 | 允许，仅返回本人记录 | 不得读取他人信用记录 | 访问范围按权限判定 |
| 未认证学生查看消息通知 | 允许，仅返回当前账号通知 | 不得读取他人通知 | 访问结果可追溯 |
| 已认证学生下架他人商品 | 仅限本人发布的商品 | 他人商品保持原状态 | 权限拒绝 |
| 管理员驳回举报或扣信用分 | 允许，但须满足正式业务规则 | 按正式规则更新处理结果及信用记录 | 管理操作可追溯 |

上述为可用于原型和后续系统验收的预期结果，未执行真实系统测试。状态相关场景的具体初态由正式状态转换表补齐。

## 6.4 关联字段与条件约束


- 一件商品关联一个发布学生和一个分类；一笔订单关联一名下单学生和一件商品。原文商品“分类”字段本为枚举描述，本文件统一用分类编号引用分类实体，所选类别名称来自该实体，不维护两个相互冲突的分类值。
- 评价关联评价人、被评价人及一笔订单。订单一方是下单人，另一方是商品发布人；“仅交易双方互评、完成后可评、次数限制”都须正式业务规则确认，此处仅把交易双方作为候选数据一致性条件。
- 举报学生学号必填，举报人只能是已认证学生；举报对象仅限商品，不支持举报学生或评价。处理管理员编号在未处理时可空，在处理完成时必填。处理状态、结果、处理人、处理时间应相互一致，具体处置流程待确认。管理员是处理主体，不是举报人。
- 一名学生有零到多条信用记录，每条记录可选关联一笔订单。是否以记录累计得出信用分、何时同步更新，尚无依据，不编造计算公式。拒绝访问不产生信用扣分。
- 连续登录失败次数、锁定截止时间是对原文登录保护行为的数据补充建议；锁定只约束登录，是否限制已登录会话待确认，不等同于封禁账号或改变学生认证状态。

## 7.1 状态定义

> 本节定义订单、商品、物品流转三个对象的状态集合与含义，并给出三张状态机图。
> **状态机是全系统状态语义的唯一出处**：功能需求（§3）中的前置/后置条件、数据字典（§6）中的状态字段取值、原型中的状态显示，均以此为准。


| 对象 | 状态 | 含义 |
|---|---|---|
| 订单 | 待支付 | 创建成功且商品已锁定，等待买家付款 |
| 订单 | 已支付 | 卖家已在系统内确认收款，尚未完成交付 |
| 订单 | 待交付 | 卖家已确认收款，等待线下交付 |
| 订单 | 待确认 | 卖家已提交交付记录，等待买家确认 |
| 订单 | 已完成 | 买家有效确认，成交已记录 |
| 订单 | 已取消 | 付款前取消或超时关闭，不接受新的付款转换 |
| 订单 | 退款中 | 已付款订单取消，等待线下退款完成 |
| 订单 | 已退款 | 线下退款完成的终态 |
| 商品 | 待审核 | 已提交，尚未审核通过 |
| 商品 | 在售 | 审核通过且可被下单 |
| 商品 | 已预订 | 已被一个未结束订单占用 |
| 商品 | 已售出 | 对应订单已完成 |
| 商品 | 已下架 | 审核拒绝、主动下架或违规限制，不可下单 |

- SM-01：订单状态图，建模对象为订单，关联 BR-03、BR-09～BR-14、BR-16、BR-21；源文件 `SM-01-订单状态图.drawio`，导出 `SM-01-订单状态图.png`。
- SM-02：商品状态图，建模对象为商品，关联 BR-08、BR-09、BR-13、BR-14、BR-16、BR-20；源文件 `SM-02-商品状态图.drawio`，导出 `SM-02-商品状态图.png`。
- SM-03：物品流转状态图，建模捐赠与借用物品，关联 BR-20；源文件 `物品流转状态图.drawio`，导出 `物品流转状态图.png`。捐赠链为“待领取→已预约→已转交”，可因超期无人领取或捐赠者撤回转为“已取消”；借用链为“申请中→借用中→已归还”，借用中逾期后仍可归还。
- 三图采用 UML 状态机图：圆角矩形表示状态，实心圆表示初始伪状态，靶心圆表示终止状态，带开放箭头的实线表示转换；标注采用“事件 [守卫条件] / 效果”，ST 或 FT 编号关联下表。初始转换不设置触发事件或守卫，其创建条件在 ST-01、ST-15、FT-01、FT-05 中说明。
- 已完成、已取消、已退款、已售出经无触发完成转换到达 UML 终止状态，表示本次交易或发布生命周期结束，不删除历史数据；这类符号性完成转换不新增业务 ST 编号。后续重复请求由系统按 ST 表返回既有结果。已下架仍可重新提交，不是终止状态。完整条件与异常处理以表格为准。
- 买家付款标记是待支付订单上的操作记录，不是订单主状态；退款处理仍在线下完成，平台只记录退款状态变化，不接收或核验资金。

# 8 质量需求

## 8.1 验收测试共同前提


以下测试方案均为未来验收设计，不是已经执行的真实系统测试。建议测试前提、取样数量、观察窗口与细则均为团队提议，不视为已有业务事实。

性能共同前提建议（待确认）：使用拟验收版本和同一套事先登记的测试环境，记录客户端／服务环境配置、浏览器版本、校园网络条件、往返时延与可用带宽；建议受控网络往返时延 ≤ 50 毫秒、每客户端可用带宽 ≥ 10 Mbps。使用不含真实隐私的测试数据；图片建议每张 ≤ 500 KB，并记录每条商品的图片数量、总大小及首屏数量。正式业务数据更大时应增加相应场景，不能缩小数据规避指标。所有端到端时间均从用户动作发起计至明确结果呈现，不能只量内部处理时间。

原文未明确响应时间是最大值、平均值还是分位数，本文件按有效样本逐次满足原阈值编写，以避免放宽要求；最终统计口径仍列为待确认。工具故障等无效样本须有依据；系统异常、超时及失败必须保留并单列，不得只对成功样本宣称整体达标。

| 需求描述与依据 | 原文要求：可用性 ≥ 99%，考试周等高峰期也要可用。 |
| 测试前提／适用范围 | 建议值，待确认：按校园当地时间每个自然月统计，服务窗口为全天 24 小时，计划维护也计入不可用时间；检查公开浏览、登录和满足业务条件的合法下单。考试周按学校校历确定，另按完整考试周统计，不能用平峰月均值掩盖高峰故障。 |
| 量化指标与统计口径 | 可用性＝（应服务总分钟数－不可用分钟数）÷应服务总分钟数×100%，每月 ≥ 99%；建议考试周单独同样 ≥ 99%。以 30 天月为例，总计 43200 分钟，最多不可用 432 分钟。建议值，待确认：每 1 分钟检查一次，任一关键功能在可控正常条件下失败则该分钟不可用，多功能同时失败只累计一次。 |
| 验收方式 | 核查监测原始记录、故障和维护时间并计算；真实正常权限拒绝、学生个人网络故障不算系统故障，服务端故障及其依赖故障导致不可访问计入。检查可通过重复探测排除单点客户端故障，但确认后的故障从首次失败计起。统计周期未满只能提供阶段结果；不得把短时压力测试等同月度 99% 已达标。 |

## 8.10 与数据及权限的对应

## 一、角色与身份

| 术语 | 定义 | 备注 |
|---|---|---|
| **游客** | 未登录的访问者，只能浏览商品，不能交易 | |
| **学生** | 通过学校统一身份认证接入平台的在校学生 | 平台唯一的一类自然人用户角色 |
| **未认证学生** | 已登录但实名核验未通过的学生，不能发布、下单 | 目标系统内的一个账号状态，不是新角色 |
| **已认证学生** | 实名核验已通过的学生，可发布、下单、评价、举报 | |
| **管理员** | 负责商品审核与违规处置的平台运营人员 | **独立编号，不由学生身份升级而来** |
| **参与者** | 位于系统边界之外、与系统交互的人、设备或外部系统 | 用例图用词 |

## 二、身份与认证

| 术语 | 定义 |
|---|---|
| **学校统一身份认证** | 学校已有的身份认证系统（**外部系统**）。平台调用它核验学生身份并取得学号，不自建账号体系 |
| **学号** | 由学校分配的学生唯一标识，作为平台内学生账号的唯一键 |
| **实名认证 / 身份核验** | 通过学校统一身份认证确认「该用户是本校学生」的过程。**不是**手工上传身份证 |
| **账号状态** | 学生账号的核验状态，取值：`未认证`、`已认证`、`受限`、`封禁` |

> ⚠️ **不用「注册」「密码」这两个词**：平台不自建账号体系，注册不存在；
> 学生用学校密码登录，平台不接触密码。

## 三、商品

| 术语 | 定义 |
|---|---|
| **商品** | 学生发布的一件待售二手物品，是平台的核心交易对象 |
| **分类** | 商品所属的类别，**用分类实体承载**，一件商品属于且仅属于 1 个分类；同一分类下可有 0..* 件商品。分类**不分层** |
| **商品状态** | 商品在其生命周期中所处的状态，共 **5 种**（见下） |
| **在售** | 商品已上架、未被任何买家预订，可被下单 |
| **在售上限** | 同一学号可同时处于「在售」状态的商品数量上限（数值见业务规则） |
| **成交** | 买家确认收货，订单完成的这一刻 |

### 商品状态取值（5 种，三处必须一致）

| 状态 | 含义 | 可否下单 |
|---|---|---|
| `待审核` | 已发布但尚未通过管理员审核，仅发布者可见 | 否 |
| `在售` | 已通过审核，可被下单 | **是** |
| `已预订` | 已被某买家下单、订单未取消也未完成 | 否 |
| `已售出` | 交易完成，终态 | 否 |
| `已下架` | 被卖家主动撤下，或被管理员强制处置 | 否 |

> **初始状态恒为 `待审核`。** 一件商品**同一时刻只能有一个有效订单**，历史订单可有 0..* 个。

## 四、交易与订单

| 术语 | 定义 |
|---|---|
| **订单** | 买家对一件商品发起的一次购买行为，记录交易全过程 |
| **有效订单** | 状态不是 `已取消` 或 `已退款` 的订单。一件商品同时最多 1 个 |
| **历史订单** | 该商品上已结束（取消 / 退款 / 完成）的订单，用于留痕，数量 0..* |
| **自购** | 买家下单自己发布的商品，**平台禁止** |
| **价格** | 商品的标价。平台不做议价，下单即以标价成交 |
| **确认收货** | 买家确认已实际拿到商品，订单据此完成。**这是唯一的成交判据** |

### 订单状态取值

| 状态 | 含义 | 下一步 |
|---|---|---|
| `待支付` | 订单已生成，等待买家付款 | → `已支付` / `已取消` |
| `已支付` | 买家已标记付款且卖家已确认收款 | → `待交付` |
| `待交付` | 双方已约定交付安排，等待实际交付 | → `待确认` |
| `待确认` | 商品已交付到买家手中，等待买家确认 | → `已完成` |
| `已完成` | 买家确认收货，交易完成，终态 | — |
| `已取消` | 订单被取消（主动取消 / 超时未付），终态 | — |
| `退款中` | 已支付后取消，等待卖家退款 | → `已退款` |
| `已退款` | 退款完成，终态 | — |

> ⚠️ **不要用「待完成」这个状态**——它把「待支付 / 已支付 / 待交付 / 待确认」四件事混成一个，状态机就画不下去了。

## 五、支付（平台不碰钱）

| 术语 | 定义 |
|---|---|
| **第三方支付** | 买家与卖家之间完成货币转移的**外部系统**（微信/支付宝等）。平台不接入、不托管、不分账 |
| **标记已付款** | 买家在平台内声明「我已在第三方完成转账」的动作 |
| **确认收款** | 卖家在平台内核对到账后确认的动作。**没有这一步，订单不能进入 `已支付`** |
| **交易参考信息** | 平台允许保留的非敏感信息，例如付款时间、金额、订单号 |
| **敏感支付信息** | 支付密码、银行卡号、验证码等。**平台一律不得存储** |

## 六、交付

| 术语 | 定义 |
|---|---|
| **交付** | 把商品实际交到买家手中的过程。**全程在线下完成**，平台不提供物流 |
| **交付方式** | 取值：`见面交付`、`自提点`。下单时必须选定其一 |
| **见面交付** | 买卖双方在系统内协商时间与地点后当面交货 |
| **自提点** | 校内设置的线下取货地点（**外部组织**）。卖家送到后**由学生本人在系统内点「已送达自提点」登记到件**；买家凭码取件后**自行点「我已取货」确认**。<br>⚠️ 自提点值守人**不是平台角色**——不登录、无账号、无权限 |
| **交付安排** | 双方就交付方式、时间、地点达成的约定，由平台记录并通知双方 |
| **协商未达成** | 双方就时间地点反复修改仍无法一致，任一方可申请取消订单 |

## 七、信用与评价

| 术语 | 定义 |
|---|---|
| **信用分** | 反映学生交易行为的分数，用于限制其发布 / 交易权限。<br>**初始值 100，取值范围 0~150**（组长裁定 v1.2）。**加减分事件与幅度见业务规则 BR-21**（不由本条定义） |
| **信用分阈值** | `信用分 < 60` → **禁止发布新商品**（已发布商品仍可交易到底）；`信用分 < 40` → **禁止下单**（进行中的订单不受影响） |
| **信用记录** | 信用分的一次变动流水，含变动原因、幅度、时间、关联订单。**每次变动必须留一条**，不可直接改分数 |
| **评价** | 订单完成后，交易双方对对方的评价。**双向**、每方每单 1 次、**不可修改** |
| **评价资格** | 仅 `已完成` 订单的交易双方可评价，每方每单限 1 次 |

## 八、治理

| 术语 | 定义 |
|---|---|
| **举报** | 已认证学生对**商品**发起的违规申告。举报对象**仅限商品** |
| **审核** | 管理员对 `待审核` 商品做上架前准入判断，结论：通过 / 不通过 |
| **处置** | 管理员对已上架违规商品的处理，手段包括：强制下架、扣信用分、驳回举报 |
| **强制下架** | 管理员处置导致的商品下架，与卖家主动下架**执行角色不同**，状态转换表中分两行记录 |

## 九、物品流转（非交易）

| 术语 | 定义 |
|---|---|
| **物品流转** | 二手物品在无偿或非买卖场景下的转移，包含：捐赠、回收、借用。**明确不含买卖交易** |
| **捐赠** | 学生把物品无偿转让给受赠方 |
| **回收** | 学生把废弃物品交由回收方处理 |
| **借用** | 学生把物品在规定期限内借出，到期归还。**所有权不转移** |
