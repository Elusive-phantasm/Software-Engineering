# 部署与运行手册

---

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11、Linux、macOS | 本项目在 Windows 11 + PowerShell 7 下开发与验证 |
| Node.js | **≥ 22.5.0** | 依赖内置 `node:sqlite`；`node -v` 自查 |
| 磁盘 | 约 300 MB | 含 `node_modules`（express 及其依赖）与运行数据 |
| 网络 | 安装依赖时需要 | 装完即可完全离线运行 |
| 浏览器 | Chrome / Edge / Firefox 现代版 | 使用 ES Module、`fetch`、canvas |

> 不需要 MySQL、不需要 Maven/JDK、不需要编译原生模块。

---

## 2. 安装与启动

```bash
cd app

# 1) 安装依赖（只有 express）
npm install --cache ./.npm-cache

# 2) 灌入演示数据（首次；会清空并重建 data/platform.db）
npm run seed

# 3) 启动
npm start
```

Windows 也可双击 **`启动.bat`**：自动检测依赖与数据库、打印入口与演示账号。

启动输出示例：

```
  ┌──────────────────────────────────────────────────────────┐
  │  拾光二手 · 校园二手交易平台（需求规格说明书 V2.1 实现）  │
  └──────────────────────────────────────────────────────────┘
  学生端： http://127.0.0.1:3081/
  管理端： http://127.0.0.1:3081/admin
  时间：   2026-11-08T15:11:08Z    邮件通道：local
```

| 端口 | 用途 | 修改方式 |
|---|---|---|
| 3081 | HTTP 服务 | `config/default.json` → `server.port`，或环境变量 `PORT` |
| — | 数据库 | `data/platform.db`（SQLite 单文件，WAL 模式会附带 `-wal`/`-shm`） |

### 常用命令

| 命令 | 作用 |
|---|---|
| `npm start` | 启动服务 |
| `npm run dev` | 启动并在源码变更时自动重启（`node --watch`） |
| `npm run seed` | **清库重灌**演示数据 |
| `npm run seed:keep` | 仅当库为空时灌入（等价首次启动的自动行为） |
| `npm test` | 跑全部验收测试（需服务已启动） |
| `npm run mail:setup` | 交互式配置真实 SMTP 发信（自检 + 写配置 + 发测试邮件） |
| `npm run mail:test -- you@mail.com` | 邮件通道自检（按当前配置发一封） |

## 3. 配置真实 SMTP 发信

默认 `transport=local`：验证码写入 `data/mailbox.jsonl`，可通过学生端右下角扳手面板或 `GET /api/dev/mailbox` 查看——**离线也能完整演示注册与找回密码**。

要真实发信，两种方式任选：

### 方式 A：交互式向导（推荐，不用手改 JSON）

```bash
npm run mail:setup
```

按提示选择服务商 → 填发件邮箱 → 粘贴授权码 → 脚本会
① 先做 SMTP 握手与认证自检（不发信，失败会告诉你原因）；
② 把配置写入 `config/mail.json`（已被 `.gitignore` 忽略）；
③ 发一封测试邮件到你指定的地址；
④ 提示重启服务。

> 该脚本必须在**本机终端**里交互运行（不要在非交互环境里管道喂入，脚本会直接提示并退出）。

### 方式 B：手工填配置文件

```bash
# 1) 复制模板
copy config\mail.example.json config\mail.json      # Windows
cp config/mail.example.json config/mail.json        # Linux/macOS
```

2) 填写真实凭据（以 QQ 邮箱为例）：

```json
{
  "transport": "smtp",
  "host": "smtp.qq.com",
  "port": 465,
  "secure": true,
  "user": "你的QQ邮箱@qq.com",
  "pass": "SMTP 授权码（在邮箱设置里生成，不是登录密码）",
  "from": "拾光二手 <你的QQ邮箱@qq.com>"
}
```

3) 自检并重启：

```bash
npm run mail:test -- 你的收件邮箱
npm start
```

支持的发信方式：

| 场景 | 配置 |
|---|---|
| 465 端口隐式 TLS | `"secure": true`（默认） |
| 587 端口 STARTTLS | `"secure": false, "requireTLS": true` |
| 认证方式 | 自动选择 `AUTH PLAIN` 或 `AUTH LOGIN` |
| 自签名证书（内网测试） | `"allowInvalidCert": true`（**生产不要开**） |

> `config/mail.json` 已被 `.gitignore` 忽略，**不要把授权码提交到仓库**。
> 若 SMTP 不可用而 `transport=smtp`，注册会明确失败并提示"验证码发送失败"（UC-01 辅事件流 I），不会静默成功。

## 4. 生产部署注意事项

| 事项 | 做法 |
|---|---|
| 关闭演示工具 | `config/default.json` → `"server": { "enableDevTools": false }`（`/api/dev/*` 全部返回 403，时间偏移接口不可达） |
| 重置演示时间/数据 | 关闭前先 `POST /api/dev/time-reset` 归零偏移 |
| 管理员初始密码 | 种子管理员 `ADM-001` 的 `must_change_password` 置为 0 以便演示；正式交付请改为 1 并在首登后改密（`POST /api/admin/auth/change-password`） |
| Cookie 安全 | 若通过 HTTPS 暴露，把 `src/http/routes/auth.routes.js` 中 `cookieOptions().secure` 改为 `true` |
| 反向代理 | Nginx/Apache 反代到 `127.0.0.1:3081` 即可；注意透传 `Host` 与 `Cookie`，本项目未依赖 `X-Forwarded-*` |
| 进程守护 | Windows 可用 `nssm`；Linux 可用 systemd/pm2，工作目录设为 `app/`，启动命令 `node src/server.js` |
| 备份 | 备份整个 `data/` 目录（数据库 + 上传图片 + 发件箱 + 密钥文件 `secret.key`）。**`secret.key` 丢失会导致所有验证码摘要与令牌失效（用户需重新获取验证码、重新登录）** |
| 数据库维护 | 定期 `VACUUM`；WAL 文件随 checkpoint 自动收缩 |
| 多实例 | **不支持**：SQLite 单写者 + 本地文件存储。若需水平扩展，需换 PostgreSQL/MySQL 并把图片移到对象存储 |
| 日志 | 服务端输出到 stdout；审计日志在 `audit_logs` 表（不含密码、完整手机号、宿舍地址、学生证图片内容） |

## 5. 排错

| 现象 | 原因与处理 |
|---|---|
| `npm install` 报 `EPERM`/`error writing to the directory` | 沙箱或权限导致 npm 写全局缓存失败。加 `--cache ./.npm-cache`（本项目自带 `.gitignore` 已忽略该目录） |
| 启动报 `Cannot find module 'node:sqlite'` | Node 版本低于 22.5，升级 Node |
| 输出 `ExperimentalWarning: SQLite is an experimental feature` | 正常提示；`npm start` 已用 `--no-warnings` 屏蔽。若自行 `node src/server.js` 会看到 |
| 端口被占用 `EADDRINUSE` | 换端口：`set PORT=3082 && npm start`（Windows）或修改 `config/default.json` |
| 注册收不到验证码 | `transport=local` 时验证码只在开发发件箱：点学生端右下角扳手，或访问 `/api/dev/mailbox` |
| 邮箱验证码总是"错误或已失效" | 检查：① 是否超过 10 分钟；② 是否已用过（一次性）；③ 是否连续输错 5 次（该验证码已作废） |
| 登录提示"账号已暂时锁定" | 连续 5 次密码错误锁定 15 分钟（NFR-05）。等待或用演示工具 `+0.26 小时` 后重试 |
| 学生一直被提示"请先完成学生证核验" | 认证状态不是「已认证」：用管理员账号审核其申请，或（演示）`POST /api/dev/set-cert` |
| 管理员看不到待审核商品 | 卖家可能未通过认证、或商品已不在「待审核」；后台商品审核页只看 `status=待审核` |
| 时间偏移忘记归零导致判定异常 | 学生端扳手面板 → `−7 天` 调回，或 `POST /api/dev/time-reset`；`data/platform.db` 的 `settings.time_offset_ms` 记录当前偏移 |
| 想彻底重来 | 停止服务 → 删除 `data/` 目录 → `npm run seed` → `npm start` |

## 6. 卸载/清理

```bash
# 只清业务数据，保留依赖
rm -rf data/          # Windows: rmdir /s /q data

# 完全清理
rm -rf node_modules data .npm-cache package-lock.json
```
