# 需求追踪矩阵（UC / BR / ST / AT / NFR → 实现 → 验证）

> 需求基线：《校园二手交易平台 软件需求规格说明书 V2.1》。
> 本矩阵逐条给出「需求条目 → 代码位置 → 对外接口 → 自动化验收断言」，
> 用于回答评审的三个问题：**做了没有、在哪做的、怎么证明做对了**。
>
> 测试套件：`tests/uc/run-uc.js`（238 项断言）、`tests/sc/run-sc.js`（127 项断言）、`tests/ui/run-ui.js`（29 项前端渲染断言）、`tests/smoke.js`（9 项）。
> 表中「验证」列写的是被断言的**可观测行为**，不是实现细节。

---

## 2. 业务规则（22 条）

| 规则 | 要点 | 实现位置 | 硬保证（不是"提示"，是机制） | 验证 |
|---|---|---|---|---|
| BR-01 | 已认证且未封禁才可发布/下单；不可自购 | `guards.js` `requirePublishRights` `requireOrderRights`；`order.service.js` `createOrder` | 守卫函数统一校验 + 订单表 `CHECK (buyer_id <> seller_id)` | 未认证/封禁/自购全部拒绝 |
| BR-02 | 同学生最多 5 件在售 | `guards.js` `assertOnSaleQuota` | 发布与重提前统一计算在售数 | 第 6 件被拒「在售商品已达 5 件」 |
| BR-03 | 发布即待审核；驳回进已下架；重提需重审 | `product.service.js` `createProduct` `rejectProduct` `resubmitProduct` | 商品状态 `CHECK` 约束 + 服务层状态机 | 见 SC-04 |
| BR-04 | 禁售清单闭集（A1–E2）；举报须核实后处置；举报对象可为商品或学生 | `core/rules.js` `FORBIDDEN_CATEGORIES`；`report.service.js` `submitReport` `handleReport` | 18 类闭集常量；驳回原因必须引用类目编号；举报类型×对象 组合校验（服务层 + 表 `CHECK`） | SC-13 逐类驳回；类型不匹配拒绝 |
| BR-05 | 价格 > 0 且 ≤ 50000，最多 2 位小数；成交金额＝标价 | `rules.js` `validatePrice`；`order.service.js` 取 `price_cents` | 价格以「分」存整数；表 `CHECK (price_cents > 0 AND <= 5000000)` | 0 / 50000.01 / 三位小数拒绝；成交金额等于标价 |
| BR-06 | 下单即成交，原子且唯一；重复请求不重复成交 | `order.service.js` `createOrder`；`schema.sql` | `tx()` 串行事务 + `UPDATE ... WHERE status='在售'` 条件更新 + **部分唯一索引 `ux_orders_one_valid`** | SC-03 并发仅一笔成功；重复提交返回同一订单 |
| BR-07 | 平台不碰钱货：不存支付信息、不记交付 | 全局：无支付/交付字段与接口 | 数据字典中不存在相关字段（结构性保证） | 接口无任何支付/交付入参 |

| BR-09 | 卖家仅可下架本人在售；管理员可下架待审核与在售；已售出任何角色不可下架；仅已下架可删除 | `product.service.js` `takeDownProduct` `deleteProduct` | 状态与归属双重校验；软删除写 `deleted_at` 并从所有列表排除 | 在售删除被拒、已售出不可下架、删除后不可访问 |
| BR-10 | 封禁禁止发布与下单，仍可浏览；封禁须连带下架在售与待审核商品 | `admin.service.js` `setAccountStatus`；`product.service.js` `offShelfAllForBannedSeller` | 同一事务内改账号状态 + 批量下架（ST-13） | SC-12：在售与待审全部转「已下架（管理员违规下架）」，已售出不受影响 |

## 3. 状态转换（ST-01～ST-13 / AT-01～AT-08）

| 编号 | 转换 | 实现位置 | 验证 |
|---|---|---|---|
| ST-01 | 无 → 待审核（发布） | `product.service.js` `createProduct` | 创建后状态恒为「待审核」 |
| ST-02 | 待审核 → 在售（审核通过） | `approveProduct` | 通过后对外可见 |
| ST-03 | 待审核 → 已下架（审核不通过） | `rejectProduct` | 原因必含 §4.3 类目编号 |
| ST-04 | 待审核 → 已下架（卖家撤回） | `withdrawProduct` | 下架原因＝卖家撤回 |
| ST-05 | 在售 → 已售出（下单成交，同事务建单） | `order.service.js` `createOrder` | 订单与商品状态同事务，失败整体回滚 |
| ST-06 | 在售 → 已下架（卖家主动下架） | `takeDownProduct` | 下架原因＝卖家主动下架 + 通知收藏者 |
| ST-07 | 在售 → 已下架（管理员违规下架） | `report.service.js` `handleReport`；`product.service.js` `forceOffShelfProduct` | 下架原因＝管理员违规下架 + 扣 −10 |
| ST-08 | 已下架 → 待审核（修改后重新提交） | `resubmitProduct` | 仅「审核不通过 / 卖家撤回」可重提，编号不变 |
| ST-09 | 已下架 → 在售（撤销违规处置） | `restoreProduct` | 仅管理员违规下架商品可恢复，扣分不回滚 |
| ST-10 | 已售出 → 在售（单方撤销成交） | `order.service.js` `cancelOrder` | 商品回在售、成交置已撤销、判定置待判定 |
| ST-11 | 已售出 → 已下架（撤销时卖家已封禁） | `cancelOrder` → `product.service.js` `offShelfAfterCancel` | 下架原因＝撤销后不可交易 |
| ST-12 | 在售 → 待审核（卖家编辑） | `updateProduct` | 清空下架原因、刷新发布时间、编号不变 |
| ST-13 | 在售/待审核 → 已下架（封禁联动） | `offShelfAllForBannedSeller` | 与封禁同一处置动作完成 |
| AT-01 | 无账号 → 未提交（注册） | `auth.service.js` `register` | 注册后 `cert_status='未提交'` |
| AT-02 | 未提交 → 待审核（提交核验） | `verification.service.js` `submitVerification` | 同时最多一条待审核申请（部分唯一索引） |
| AT-03 | 待审核 → 已认证（核验通过） | `approveApplication` | 学号写入并唯一锁定 |
| AT-04 | 待审核 → 已驳回（核验驳回） | `rejectApplication` | 重提次数 +1 |
| AT-05 | 已驳回 → 待审核（重新提交） | `submitVerification` | 未达 3 次上限 |
| AT-06 | 审核超 24 小时（**状态保持**） | `scheduler.service.js` | 仍为待审核，仅提醒 + 计超时 |
| AT-07 | 注册满 7 天未提交（**状态保持**） | `taskCertSubmitReminder` | 每日提醒，不自动驳回/封禁 |
| AT-08 | 已认证 → 已驳回（事后核实伪造） | `revokeCertification` | 同事务封禁 + 联动下架（BR-18） |

**不存在的转换（出现即缺陷）**：已售出 → 待审核、已下架 → 已售出、待审核 → 已售出。代码里没有任何路径能产生它们。

## 4. 质量需求（NFR-01～NFR-10）

| 编号 | 需求 | 实现与验证方式 | 说明 |
|---|---|---|---|
| NFR-01 | 商品列表 ≤ 2 秒 | 列表查询单表 + 索引 `ix_products_status`；分页 12 条 | `tests/sc` 中列表接口稳定在毫秒级；正式压测需按 §8.2 方案执行，本项目未做 50 并发压测 |
