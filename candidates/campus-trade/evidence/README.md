# evidence/ 证据目录说明

> 用途：存放「精选测试与审查证据」，供阶段验收与答辩核查。
> 原则：**证据必须可复现**——命令、环境、版本、原始输出齐全；不接受只有「全绿」摘要。

## 1 目录与命名

```text
evidence/
  S1/  S1-TASK-03-price-boundary-20261112.log
  S2/  S2-TASK-05-concurrent-order-20261115.log
  S3/  S3-TASK-06-message-forbidden-20261120.log
  review/  review-TASK-03-20261112.md
  acceptance/  acceptance-S1-20261113.md
```

命名：`<阶段>-<任务>-<场景>-<日期>.<扩展名>`；同一场景多次执行加序号（`-2`）。

## 3 每条证据至少包含

1. 执行时间、代码版本/提交标识、环境（JDK/Node/MySQL 版本与端口）。
2. 完整命令（可直接复制重跑）。
3. 原始输出（含失败样本；失败不得删除）。
4. 判定结论（通过/失败/阻塞）与判定人。

## 4 禁止事项

- 只交截图不交命令；只交通过项不交失败项；修改或拼接原始输出。
- 用内存 Mock 或顺序调用冒充并发验证。
- 用本地开发邮箱冒充真实邮件服务。
- 在证据里出现真实手机号、宿舍地址、学生证图片内容或明文验证码。
