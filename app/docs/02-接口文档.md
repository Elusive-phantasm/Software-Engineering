# 接口文档（REST API）

> 基地址：`http://127.0.0.1:3081`
> 所有接口返回统一信封：

```json
{ "ok": true,  "data": { }, "message": "可选提示语" }
{ "ok": false, "code": "PERMISSION_DENIED", "message": "请先上传学生证", "extra": null }
```

**鉴权**：登录成功后服务端下发 `sgsid` Cookie（HttpOnly、SameSite=Lax）。学生端与管理端会话相互独立，同一浏览器可同时持有两个会话。

**错误码与 HTTP 状态**

| code | HTTP | 含义 | 处理口径 |
|---|---|---|---|
| `AUTH_REQUIRED` | 401 | 未登录 / 会话失效 | 引导登录 |
| `PERMISSION_DENIED` | 403 | 角色或对象归属无权（§5.2） | 提示语直接展示；**不改数据、不扣分** |
| `STATE_REJECTED` | 409 | 角色有权但业务状态不满足（§5.5 第 3 条） | 提示语直接展示；不改数据 |
| `CONFLICT` | 409 | 组合唯一冲突（重复邮箱、重复举报、并发成交等） | 提示重试或查看现状 |
| `VALIDATION_FAILED` | 422 | 字段校验失败 / 业务前置不满足 | 就地提示 |
| `RATE_LIMITED` | 429 | 登录锁定、验证码频控 | 提示等待 |
| `NOT_FOUND` | 404 | 对象不存在或已删除（不泄露历史） | 提示不可用 |
| `INTERNAL` | 500 | 未预期异常 | 提示稍后重试（不发敏感信息） |

`message` 字段的文案严格取自需求文档 §5.2 的「拒绝提示语」表，前端直接展示，不再二次加工。

## 1. 账号与登录

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `GET` | `/api/auth/me` | 任意 | 当前会话主体：`{kind:'guest'|'student'|'admin', student?|admin?}` |
| `POST` | `/api/auth/send-code` | 游客 | 发送注册验证码 `{email}` |
| `POST` | `/api/auth/register` | 游客 | 注册 `{email, code, nickname, realName, password, phone?, agree}` |
| `POST` | `/api/auth/login` | 游客 | 学生登录 `{email, password}` → 下发 Cookie |
| `POST` | `/api/auth/logout` | 已登录 | 退出（吊销当前会话） |
| `POST` | `/api/auth/forgot/send-code` | 游客 | 找回密码验证码 `{email}`（**响应与邮箱是否存在无关**） |
| `POST` | `/api/auth/forgot/reset` | 游客 | 重置密码 `{email, code, newPassword}` → 该账号全部会话失效 |
| `PATCH` | `/api/me/profile` | 学生 | 修改本人资料 `{nickname?, realName?, phone?, dorm?}` |
| `POST` | `/api/admin/auth/login` | 游客 | 管理员登录 `{adminId, password}` |
| `POST` | `/api/admin/auth/change-password` | 管理员 | 修改管理员密码 `{oldPassword, newPassword}` |

**校验要点**：邮箱格式与唯一、密码至少 8 位且含字母与数字、昵称/真实姓名 1–20 字、手机号 11 位（可选）、必须勾选协议。
**响应示例（注册）**

```json
{ "ok": true, "data": { "student": { "id": "STU-XXXX", "nickname": "新同学", "certStatus": "未提交", "accountStatus": "正常", "creditScore": 100, "certified": false } }, "message": "注册成功，请提交学生证核验" }
```

## 3. 商品

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `GET` | `/api/categories` | 任意 | 单层分类 + 各类在售数 |
| `GET` | `/api/products` | 任意 | 列表检索。参数：`keyword`、`categoryId`、`condition`、`minPrice`、`maxPrice`、`sort`(latest/priceAsc/priceDesc/hot)、`page`、`pageSize`；**只返回「在售」** |
| `GET` | `/api/products/:id` | 任意 | 详情。在售/已售出公开；待审核/已下架仅发布人与管理员可见。非本人浏览累加 `浏览数` |
| `POST` | `/api/products` | 已认证学生 | 发布 `{title, description, price, condition, categoryId, images[]}` → 恒为「待审核」 |
| `PATCH` | `/api/products/:id` | 本人 | 编辑（BR-22）：在售→待审核；待审核→刷新排队；系统字段被丢弃 |
| `POST` | `/api/products/:id/withdraw` | 本人 | ST-04 撤回（仅待审核） |
| `POST` | `/api/products/:id/take-down` | 本人 | ST-06 卖家主动下架（仅在售） |
| `DELETE` | `/api/products/:id` | 本人 | BR-09 软删除（仅已下架） |
| `POST` | `/api/products/:id/resubmit` | 本人 | ST-08 修改后重新提交（仅「审核不通过」「卖家撤回」） |
| `GET` | `/api/me/products` | 学生 | 「我的商品」按 待审核/在售/已售出/已下架 四组返回，附可执行动作标记 |

**商品字段约束**：`title` 1–50、`description` 1–1000（纯文本，含站外联系方式或广告时拒绝）、`price` >0 且 ≤50000 且最多 2 位小数、`condition` ∈ {全新,九成新,七成新,其他}、`images` 1–9 张。

## 5. 订单（成交记录）与评价

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `POST` | `/api/orders` | 已认证学生 | ST-05 下单成交 `{productId}`；原子切换商品状态并建单；重复提交返回同一订单 |
| `GET` | `/api/me/orders?role=all|buyer|seller` | 学生 | 成交记录（无状态分组，按成交时间倒序），附 `canReview`/`canCancel`/`canJudge`/剩余天数 |
| `GET` | `/api/orders/:id` | 成交双方 | 订单详情（管理员亦可） |
| `POST` | `/api/orders/:id/cancel` | 当事人 | UC-31 撤销 `{reason}`，原因须为固定五项之一 |
| `POST` | `/api/orders/:id/cancel-judgement` | **对方** | 免责判定 `{judgement:'已免责'|'计违约'}` |
| `POST` | `/api/orders/:id/reviews` | 成交双方 | UC-14 评价 `{content}`（仅文字，1–500 字） |
| `GET` | `/api/me/reviews/written` | 学生 | 我发出的评价 |
| `GET` | `/api/me/reviews/received` | 学生 | 我收到的评价 |

**撤销原因枚举**：`买家不想要了` / `卖家不卖了` / `货物与描述不符` / `约不上时间` / `其他`。
**订单对象关键字段**：`status`（有效/已撤销）、`cancelInitiatorId`、`cancelReason`、`cancelledAt`、`cancelJudgement`（待判定/已免责/计违约）、`judgementAt`、`amount`（=下单时标价）。

## 6. 举报与处置

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `POST` | `/api/reports` | 已认证学生 | UC-12 举报 `{targetType:'商品'|'学生', targetId, type, reason}` |
| `GET` | `/api/me/reports` | 学生 | 我的举报与处理进度 |
| `GET` | `/api/admin/reports?status=待处理` | 管理员 | 举报队列（标明对象类型） |
| `POST` | `/api/admin/reports/:id/handle` | 管理员 | UC-13 处理 `{upheld, actions[], result, categoryCode?}` |
| `GET` | `/api/admin/meta` | 管理员 | 下拉元数据：18 类禁售清单、五项处置手段、举报类型×对象对照、撤销原因 |
| `POST` | `/api/admin/students/:id/account-status` | 管理员 | 账号处置 `{status:'正常'|'受限'|'封禁', reason, deductCredit?}`（封禁连带下架） |
| `POST` | `/api/admin/students/:id/credit` | 管理员 | 人工调分 `{delta, reason}`（幅度限 +2/−1/−2/−10） |
| `POST` | `/api/admin/products/:id/force-off` | 管理员 | ST-07 违规下架 `{reason, categoryCode}`（扣 −10） |
| `POST` | `/api/admin/products/:id/restore` | 管理员 | ST-09 撤销处置 `{reason}`（分数不回滚） |
| `POST` | `/api/admin/reviews/:id/delete` | 管理员 | 删除他人评价 `{reason}` |

**举报类型（六值）与对象匹配**：`违禁品`/`虚假描述`/`价格欺诈`/`站外导流`/`其他` 只能用于**商品**；`收款不履约` 只能用于**学生**。
**处置手段（五项）**：`警告`、`强制下架商品`、`限制发布`、`封禁账号`、`扣信用分`；对象为学生时不得包含「强制下架商品」。
**处理后果**：成立并按需勾选时 → 商品下架（ST-07）/ 账号封禁 + 联动下架（BR-10、ST-13）/ 扣 −10（BR-14 ②，每份举报最多一次）/ 学生对象另有 `被核实争议数 +1`；不成立 →「已驳回」，不产生任何处置。

## 7. 站内私信

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `POST` | `/api/messages` | 已认证学生 | UC-29 发送 `{productId, content, toId?}`；`toId` 为会话对方（卖家回复或向管理员提异议时必填） |
| `GET` | `/api/messages/conversations` | 学生/管理员 | UC-30 会话列表（对方昵称、商品、最后消息、未读数），按最后消息倒序 |
| `GET` | `/api/messages/conversations/:productId/:peerId` | 会话参与方 | 会话详情，**打开即把本人未读置读**；非参与方返回 403 且 0 条正文 |
| `GET` | `/api/messages/unread-count` | 已登录 | 私信未读总数（与通知红点独立统计） |
| `POST` | `/api/admin/messages/reply` | 管理员 | 仅可回复违规下架异议会话 `{productId, toId, content}` |

**准入规则（BR-20）**：必须绑定具体商品；只有已认证学生可发起；同一（商品, 双方）只有一条会话；接收方为管理员时商品下架原因必须是「管理员违规下架」；接收方已封禁时消息不落库、不通知，返回 409「对方账号当前不可用」。
